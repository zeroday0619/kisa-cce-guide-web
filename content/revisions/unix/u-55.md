## 개요

### 점검 내용

FTP 기본 계정에 쉘 설정 여부 점검

### 점검 목적

FTP 계정의 쉘을 통한 시스템 접근을 차단하기 위함

### 보안 위협

FTP 기본 계정에 쉘이 부여될 경우, 비인가자가 해당 기본 계정으로 시스템에 접근할 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 파일 전송 전용 계정에 대화형 shell 및 불필요한 원격 실행 권한이 제한된 경우
- **취약:** 파일 전송 전용 계정에 불필요한 대화형 shell 또는 원격 실행 권한이 부여된 경우

### 조치 방법

FTP 전용 계정의 로그인 shell 제한 및 SFTP 전용 계정의 내부 SFTP 강제

### 조치 시 영향

FTP PAM의 shell 검사 또는 SSH Match 범위 오류로 접속 중단 가능. 관리 계정과 전송 계정 구분

## 점검 및 조치 사례

### RHEL 10

1. 파일 전송 계정의 shell 및 인증 경로 확인

   ```bash command
   getent passwd ftp
   grep -nE 'pam_shells|pam_listfile' /etc/pam.d/vsftpd
   command -v nologin
   sudo sshd -T | grep -E 'forcecommand|disableforwarding'
   ```

2. FTP 전용 계정의 대화형 shell 제한

   업무 계정과 분리된 전송 전용 계정에 `usermod -s /실제/nologin/경로 USER` 적용. USER는 해당 계정으로 대체. FTP PAM의 pam_shells 검사로 전송이 차단되는 경우 인증 설계를 검토하고 nologin을 /etc/shells에 전역 추가하여 우회하지 않도록 설정

3. SFTP 전용 그룹의 별도 SSH 제한

   ```text configuration
   Match Group sftp-only
       ForceCommand internal-sftp
       DisableForwarding yes
       PermitTTY no
   ```

4. SFTP 적용 범위 및 권한 확인

   예시 그룹을 실제 승인된 SFTP 전용 그룹으로 대체하고 sshd_config의 Match 적용 범위 확인. 역할별 `/etc/ssh/sshd_config.d/60-sftp-only.conf`로 분리할 때 상위 Include가 실제로 해당 파일을 읽는지 확인. 포함 파일 끝이 Match 범위를 자동 종료하지 않으므로 뒤에 읽는 지시문의 허용 범위까지 점검하여 구문 오류 방지. 먼저 일치하는 Match의 값과 기존 제한을 `sshd -T -C user=USER,host=HOST,addr=ADDR`로 대조하고 접속 조건은 실제 전송 계정 값으로 대체. 파일시스템 접근 권한은 별도로 제한. 설정 검사 후 기존 관리자 세션을 유지한 상태로 적용

5. SSH 구문 검사 및 설정 적용

   ```bash command
   sudo sshd -t
   sudo systemctl reload sshd.service
   ```

6. 대화형 접속 제한 및 정상 전송 확인

   전송 계정의 정상 파일 전송, 대화형 shell·명령 실행·forwarding 차단 확인. 다른 관리 계정의 정상 접속 확인
