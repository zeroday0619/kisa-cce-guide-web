## 개요

### 점검 내용

로그에 대한 접근 통제 및 관리 여부 점검

### 점검 목적

로그 파일을 관리자만 제어할 수 있게 하여 비인가자의 임의적인 파일 훼손 및 변조를 방지하기 위함

### 보안 위협

로그에 대한 접근 통제가 미흡할 경우, 비인가자가 로그에서 정보를 획득하거나 로그 자체를 변조할 수 있는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 로그 생성·관리·조회 권한이 승인된 주체로 제한되고 회전 후에도 유지되는 경우
- **취약:** 비인가자가 로그를 조회·변조할 수 있거나 회전 후 권한 제한이 유지되지 않는 경우

### 조치 방법

서비스별 로그 소유자·조회 권한 제한 및 회전·재생성 정책에 권한 반영

### 조치 시 영향

권한 변경 시 로그 생성·수집 실패 가능. 서비스 계정의 필수 쓰기 및 디렉터리 탐색 권한 유지

## 점검 및 조치 사례

### RHEL 10

1. 로그 소유자·권한 및 비인가 쓰기 확인

   ```bash command
   sudo stat -c '%U:%G %a %n' /var/log
   sudo find /var/log -xdev -type f -perm /002 -ls
   sudo find /var/log -xdev -type d -perm /002 -ls
   getent group adm
   getent group systemd-journal
   ```

2. 서비스별 생성 주체와 조회 권한 확인

   journal, 인증 로그 및 애플리케이션 로그의 소유자·그룹·ACL 확인. `getfacl PATH`로 승인되지 않은 접근 항목 조사. PATH는 실제 로그 경로로 대체. 서비스의 필요한 쓰기 권한과 디렉터리 탐색 권한 보존

3. 개별 로그의 불필요한 권한 제거 예시

   ```bash command
   sudo chmod o-rwx /var/log/APP.log
   ```

4. 실제 파일의 소유자 및 모드 조정

   APP.log는 점검 대상 파일로 대체하고 서비스 소유자와 승인 조회 그룹 기준으로 조정. 이미 제한적인 0600·0640 등 권한을 넓히지 않도록 설정. 디렉터리 탐색 비트 및 journald의 systemd-journal 권한 유지. /var/log 전체 재귀 chown·chmod 금지

5. 회전 및 재생성 설정 확인

   ```bash command
   sudo logrotate --debug /etc/logrotate.conf
   systemd-tmpfiles --cat-config
   ```

6. 지속적인 권한 적용 및 기록 확인

   `/etc/logrotate.conf`의 `include /etc/logrotate.d`와 역할별 파일의 create·su 설정에서 올바른 소유자·그룹·모드 유지. 같은 로그 경로의 중복 회전 항목을 만들지 않고 기존 담당 파일 수정. tmpfiles는 `/usr/lib/tmpfiles.d`의 패키지 파일을 직접 수정하지 않고 `/etc/tmpfiles.d`에서 관리. 동일 파일명은 `/etc`가 우선하며 같은 경로의 중복 행은 단순한 마지막 값 우선 규칙이 아니므로 전체 결과 대조. 서비스가 직접 생성하는 로그는 생성 설정과 함께 조정. 정상 회전 후 새 파일과 journal의 접근 권한 확인. 승인 수집기의 조회 및 서비스 로그 기록 성공 확인. 미설치 도구는 실제 로그 관리 경로로 대체
