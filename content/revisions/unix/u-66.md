## 개요

### 점검 내용

내부 정책에 따른 시스템 로깅 설정 여부 점검

### 점검 목적

보안 사고 발생 시 원인 파악 및 각종 침해 사실 확인을 하기 위함

### 보안 위협

로깅 설정이 되어 있지 않을 경우, 원인 규명이 어려우며 법적 대응을 위한 충분한 증거로 사용할 수 없는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 로그 기록 정책이 보안 정책에 따라 설정되어 수립되어 있으며, 로그를 남기고 있는 경우
- **취약:** 로그 기록 정책 미수립 또는 정책에 따라 설정되어 있지 않거나, 로그를 남기고 있지 않은 경우

### 조치 방법

정책에 따른 지속 저장·보존·중앙 수집 설정 및 실제 로그 기록 확인

### 조치 시 영향

과도한 로그 기록으로 디스크 부족 및 개인정보 노출 가능. 보존 기간과 용량·접근 권한 함께 관리

## 점검 및 조치 사례

### RHEL 10

1. 로그 저장 및 수집 상태 확인

   ```bash command
   systemd-analyze cat-config systemd/journald.conf
   sudo journalctl --disk-usage
   sudo journalctl --list-boots
   systemctl status systemd-journald.service rsyslog.service
   ```

2. 보존·전송 정책과 실제 경로 대조

   인증·권한 상승·서비스 오류의 수집 위치, 보존 기간·용량, 중앙 수집 경로 확인. rsyslog 설치 여부나 /var/log/syslog 존재를 전제하지 않고 journal 및 별도 수집 agent의 실제 저장·전송 확인

3. 지속 저장 및 용량 제한 설정 예시

   ```text configuration
   [Journal]
   Storage=persistent
   SystemMaxUse=1G
   SystemKeepFree=1G
   ```

4. 운영 용량에 맞는 정책 반영

   `/etc/systemd/journald.conf.d/60-retention.conf`에 설정. 주 설정보다 drop-in이 우선하며 서로 다른 이름은 사전식 순서로 처리되어 단일 값은 뒤의 설정이 적용됨. 동일 이름은 `/etc` 설정이 `/run` 및 `/usr/lib`의 파일보다 우선하므로 `systemd-analyze cat-config systemd/journald.conf`에서 전체 읽기 순서 확인. 예시 용량은 실제 디스크와 로그 발생량으로 조정. 용량 제한만으로 필요한 보존 기간이 보장되지 않으므로 기간·외부 보관 정책 함께 적용. rate limit에 따른 누락 및 수집 장애 감시

5. 설정 적용 및 로그 기록 확인

   ```bash command
   sudo systemctl restart systemd-journald.service
   sudo journalctl --flush
   logger -p authpriv.notice -t security-check "Logging policy validation"
   sudo journalctl -t security-check --no-pager
   ```

6. rsyslog 분할 설정 및 구문 확인

   rsyslog를 사용하는 경우 `/etc/rsyslog.conf`의 `include(file="/etc/rsyslog.d/*.conf")` 또는 `$IncludeConfig` 활성 여부 확인. 역할별 `30-authentication.conf`, `60-forwarding.conf`는 실제 포함 디렉터리에 작성하고 기존 정책과 중복 여부 대조. 파일은 사전식 순서로 처리되며 앞선 필터의 `stop`은 뒤의 규칙 실행을 중단하므로 마지막 파일 우선 적용으로 판단 금지. 변경 후 `sudo rsyslogd -N1`로 전체 설정 검사하고 성공한 경우 rsyslog 재시작 후 실제 기록·전송 확인

7. 지속 저장 및 중앙 수집 확인

   재부팅 후 이전 boot 로그 조회와 중앙 수집기 도달 여부 확인. 외부 전송은 인증·암호화 및 전송 실패 queue 정책 적용. 로그 회전과 디스크 부족 이후 기록 지속 여부 확인
