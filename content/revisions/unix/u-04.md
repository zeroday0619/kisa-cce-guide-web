## 개요

### 점검 내용

시스템의 사용자 계정(root, 일반 사용자) 정보가 저장된 파일(`/etc/passwd`, `/etc/shadow` 등)에 사용자 계정 비밀번호가 암호화 저장 여부 점검

### 점검 목적

일부 오래된 시스템의 경우 `/etc/passwd` 파일에 비밀번호가 평문으로 저장되므로 사용자 계정 비밀번호가 암호화되어 저장되어 있는지 점검하여 비인가자의 비밀번호 파일 접근 시에도 사용자 계정 비밀번호가 안전하게 관리되고 있는지 확인하기 위함

### 보안 위협

사용자 계정 비밀번호가 저장된 파일이 유출 또는 탈취 시 평문으로 저장된 비밀번호 정보가 노출 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 비밀번호 해시를 shadow 또는 보호된 중앙 인증 저장소에 분리하여 저장하고 비인가 접근을 차단한 경우
- **취약:** 일반 사용자가 읽을 수 있는 passwd 파일 등에 비밀번호 또는 해시를 저장한 경우

### 조치 방법

로컬 비밀번호 해시를 `/etc/shadow`에 분리하여 저장하고 비인가 읽기·쓰기를 제한

### 조치 시 영향

인증 파일 불일치 시 로그인이 차단될 수 있으므로 변환 전 계정 파일 백업 및 복구 세션 확보 필요

## 점검 및 조치 사례

### RHEL 10

1. 비밀번호 해시를 출력하지 않고 `/etc/passwd`의 비밀번호 필드 사용 형태 확인

   ```bash command
   awk -F: '$2 != "x" && $2 != "*" && $2 != "!" {print $1, "shadow 분리 확인 대상"}' /etc/passwd
   sudo stat -c '%U %G %a %n' /etc/shadow
   sudo pwck -r
   ```

2. 실제로 passwd 파일에 비밀번호가 저장된 이전 시스템만 shadow 형식으로 전환. 정상 shadow 설치에는 변환 명령 실행 불필요

   ```bash command
   sudo pwconv
   sudo pwck -r
   ```

3. 변경 대상 계정의 로그인 확인 및 U-18의 shadow·gshadow·백업 파일 권한 점검. NSS·SSSD 계정은 중앙 저장소의 비밀번호 보호 정책 대조
