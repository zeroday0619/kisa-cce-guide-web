## 개요

### 점검 내용

`/etc/services` 파일 권한 적절성 여부 점검

### 점검 목적

`/etc/services` 파일을 관리자만 제어할 수 있게 하여 비인가자들의 임의적인 파일 변조를 방지하기 위함

### 보안 위협

`/etc/services` 파일의 접근 권한이 적절하지 않을 경우, 비인가 사용자가 운영 포트 번호를 변경하여 정상적인 서비스를 제한하거나 허용되지 않은 포트를 오픈하여 악성 서비스를 의도적으로 실행할 수 있는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** `/etc/services` 파일의 소유자가 `root`(또는 `bin`, `sys`)이고, 권한이 `644` 이하인 경우
- **취약:** `/etc/services` 파일의 소유자가 `root`(또는 `bin`, `sys`)가 아니거나, 권한이 `644` 이하가 아닌 경우

### 조치 방법

`/etc/services`를 root 소유로 유지하고 비인가 쓰기 권한 제거

### 조치 시 영향

일반 읽기를 제거하면 서비스 이름·포트 조회에 영향이 있을 수 있으므로 기본 0644 권한 유지

## 점검 및 조치 사례

### RHEL 10

1. 서비스 매핑 파일의 소유자·모드·ACL 확인

   ```bash command
   stat -c "%U %G %a %n" /etc/services
   getfacl -p /etc/services
   namei -l /etc/services
   ```

2. root 소유 및 기본 읽기 권한 복구

   ```bash command
   sudo chown root:root /etc/services
   sudo chmod 0644 /etc/services
   ```

3. 불필요한 명명 ACL을 제거하고 정상 매핑 조회 확인

   ```bash command
   getent services ssh
   stat -c "%U %G %a %n" /etc/services
   ```

4. 패키지 제공 매핑과 로컬 변경 이력 대조. 서비스 중지가 필요한 경우 파일의 매핑 삭제가 아닌 실제 서비스·방화벽 설정에서 조치
