## 개요

### 점검 내용

허용할 호스트에 대한 접속 IP주소 제한 및 포트 제한 설정 여부 점검

### 점검 목적

허용한 호스트만 서비스를 사용하게 하여 서비스 취약점을 이용한 외부자 공격을 방지하기 위함

### 보안 위협

허용할 호스트에 대한 IP 및 포트 제한이 적용되지 않을 경우, Telnet, FTP 같은 보안에 취약한 네트워크 서비스를 통하여 불법적인 접근 및 시스템 침해사고가 발생할 수 있는 위험이 존재함

### 참고

> **참고**
>
> `hosts.allow`·`hosts.deny`만으로 TCP wrappers를 사용하지 않는 서비스를 보호할 수 없음. IPv4·IPv6, 런타임·영구 정책과 별도 컨테이너 경로를 함께 점검

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 접속을 허용할 특정 호스트에 대한 IP주소 및 포트 제한을 설정한 경우
- **취약:** 접속을 허용할 특정 호스트에 대한 IP주소 및 포트 제한을 설정하지 않은 경우

### 조치 방법

배포판의 방화벽 관리 도구로 필요한 출발지·포트만 허용하고 비인가 입력 차단

### 조치 시 영향

방화벽 변경 시 원격 관리와 업무 통신이 차단될 수 있으므로 관리망 허용 및 콘솔 복구 경로 확보 후 적용

## 점검 및 조치 사례

### RHEL 10

1. 현재 연결 인터페이스의 zone 및 열린 포트 확인. `public`은 실제 적용 zone으로 대체

   ```bash command
   sudo firewall-cmd --get-active-zones
   sudo firewall-cmd --list-all-zones
   sudo ss -lntup
   ```

2. 관리 접속 및 필요한 서비스 출발지 목록 확정 후 현재 관리 세션과 콘솔 복구 경로 확보. firewalld와 독립 nftables 서비스를 중복 관리자로 사용하지 않음

3. 허용 관리 주소에 SSH 접근 규칙 추가. 예시 주소는 실제 관리망으로 대체하며 사용하지 않는 주소 계열은 허용 규칙 생략

   ```bash command
   sudo firewall-cmd --zone=public --add-rich-rule='rule family="ipv4" source address="192.0.2.0/24" service name="ssh" accept'
   sudo firewall-cmd --zone=public --add-rich-rule='rule family="ipv6" source address="2001:db8:100::/64" service name="ssh" accept'
   ```

4. 새 관리 연결 확인 후 전체 출발지를 허용하는 중복 SSH 서비스·포트 규칙 제거. 실제 존재하는 규칙만 제거하고 기타 zone·policy·direct 규칙의 우회 허용도 확인

   ```bash command
   sudo firewall-cmd --zone=public --remove-service=ssh
   sudo firewall-cmd --zone=public --list-all
   ```

5. 허용·비허용 출발지의 서비스 접근을 각각 확인한 후 검토한 런타임 구성을 영구 저장

   ```bash command
   sudo firewall-cmd --runtime-to-permanent
   sudo firewall-cmd --permanent --zone=public --list-all
   ```

### Ubuntu 26.04 LTS

1. UFW 활성 상태 및 실제 수신 서비스 확인. 다른 방화벽 관리자를 사용 중이면 해당 관리 경로에서 조치

   ```bash command
   sudo ufw status verbose
   sudo ufw status numbered
   sudo ss -lntup
   ```

2. 관리망 및 업무 포트 목록 확정 후 콘솔 복구 경로 확보. `/etc/default/ufw`의 IPv6 관리 여부와 실제 IPv6 listener 대조

3. 관리망의 SSH 허용 규칙 추가. 예시 주소·22번 포트는 실제 관리망 및 SSH 포트로 대체

   ```bash command
   sudo ufw allow proto tcp from 192.0.2.0/24 to any port 22
   sudo ufw allow proto tcp from 2001:db8:100::/64 to any port 22
   ```

4. 기타 필요한 업무 규칙을 모두 추가한 후 불필요한 전체 출발지 허용 규칙 제거. `RULE_NUMBER`는 직전 목록에서 확인한 번호로 대체하고 한 건 삭제할 때마다 번호 재확인

   ```bash command
   sudo ufw status numbered
   sudo ufw delete RULE_NUMBER
   sudo ufw default deny incoming
   ```

5. 비활성 상태였던 경우에만 UFW 활성화 후 새 관리 연결과 비허용 출발지 거부 확인

   ```bash command
   sudo ufw enable
   sudo ufw status verbose
   ```

### Debian 13

1. 방화벽 관리자와 nftables 유효 규칙·수신 서비스 확인. UFW 또는 firewalld 관리 환경은 해당 도구로 정책 변경

   ```bash command
   systemctl status nftables.service
   sudo nft list ruleset
   sudo ss -lntup
   ```

2. 단독 nftables 호스트의 기존 input 체인에 허용 출발지·포트를 반영하고 미허용 입력은 차단. 다음은 고정 주소 서버의 입력 체인 구성 예시이며 실제 관리망·업무 포트를 반영 후 `/etc/nftables.conf`에서 전용 `host_filter` 테이블로 관리. 예시는 이 테이블만 비우고 다시 구성하며 다른 테이블은 유지. DHCP 서버 응답 등 운영에 필요한 입력 규칙은 함께 유지

   ```text configuration
   table inet host_filter {}
   flush table inet host_filter
   table inet host_filter {
       chain input {
           type filter hook input priority filter; policy drop;
           ct state invalid drop
           ct state established,related accept
           iifname "lo" accept
           meta l4proto icmp accept
           meta l4proto ipv6-icmp accept
           ip saddr 192.0.2.0/24 tcp dport 22 accept
           ip6 saddr 2001:db8:100::/64 tcp dport 22 accept
       }
   }
   ```

3. 콘솔 복구 경로를 확보한 상태에서 전체 설정 구문 확인 후 적용. 컨테이너·라우터의 전달 및 NAT 규칙을 유지하며 기존 규칙 전체 삭제 금지

   ```bash command
   sudo nft --check --file /etc/nftables.conf
   sudo nft --file /etc/nftables.conf
   ```

4. 허용·비허용 출발지별 IPv4·IPv6 접근 확인 후 부팅 시 설정 적용 활성화

   ```bash command
   sudo systemctl enable nftables.service
   sudo nft list ruleset
   ```

5. 재부팅 점검 시 저장 설정과 유효 규칙 일치 확인. 클라우드 보안 그룹 및 컨테이너의 별도 네트워크 경로도 동일한 허용 목록과 대조
