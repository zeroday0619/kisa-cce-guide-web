## 개요

### 점검 내용

`/dev` 내 장치·런타임 객체의 용도 및 비인가 파일 존재 여부 점검

### 점검 목적

허용한 호스트만 서비스를 사용하게 하여 서비스 취약점을 이용한 외부자 공격을 방지하기 위함

### 보안 위협

공격자는 rootkit 설정 파일들을 서버 관리자가 쉽게 발견하지 못하도록 `/dev` 디렉터리에 device 파일인 것처럼 위장하는 수법을 사용하는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** `/dev` 객체의 용도와 생성 주체를 확인하고 비인가 파일을 처리한 경우
- **취약:** `/dev`의 용도 불명 또는 비인가 객체를 조사 없이 방치한 경우

### 조치 방법

`/dev`의 객체 생성 근거를 확인하여 비인가 파일을 정리하고 원인 프로세스·udev 규칙 수정

### 조치 시 영향

정상 장치 노드·IPC 객체·링크 삭제 시 즉시 서비스 장애가 발생할 수 있으므로 유형만으로 삭제하지 않고 생성 주체 확인 후 처리

## 점검 및 조치 사례

### RHEL 10

1. `/dev`와 하위 파일시스템의 마운트 및 장치 관리 상태 확인

   ```bash command
   findmnt --submounts --mountpoint /dev
   systemctl status systemd-udevd.service
   ```

2. 같은 파일시스템 내 일반 파일 및 링크 목록 확인. `/dev/shm`·`/dev/pts` 등 별도 마운트는 용도를 구분하여 조사

   ```bash command
   sudo find /dev -xdev -type f -ls
   sudo find /dev -xdev -type l -ls
   ```

3. 의심 객체의 파일 유형·장치 번호·udev 정보·생성 시점 확인. `/dev/OBJECT`는 실제 점검 대상으로 대체

   ```bash command
   stat /dev/OBJECT
   udevadm info --query=all --name=/dev/OBJECT
   ```

4. 정상 IPC·장치·표준 링크를 제외하고 비인가 파일의 소유자와 생성 프로세스 확인. 침해 의심 시 증거 보존 후 사고 대응 절차에서 격리·제거

5. 원인 서비스 또는 udev 규칙 수정 후 동일 객체의 재생성 여부 및 장치 정상 동작 확인
