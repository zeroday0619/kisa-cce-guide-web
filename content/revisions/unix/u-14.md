## 개요

### 점검 내용

root 계정의 `PATH` 환경변수에 `.`(마침표)이 포함 여부 점검

### 점검 목적

비인가자가 불법적으로 생성한 디렉터리 및 명령어를 우선으로 실행되지 않도록 설정하기 위함

### 보안 위협

root 계정의 `PATH` 환경변수에 정상적인 관리자 명령어(`ls`, `mv`, `cp` 등)의 디렉터리 경로보다 현재 디렉터리를 지칭하는 `.` 표시가 우선하면 현재 디렉터리에 변조된 명령어를 삽입하여 관리자 명령어 입력 시 악의적인 기능이 실행될 수 있는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** root 홈과 명령 검색 경로에 비인가 쓰기가 없고 PATH에 현재 디렉터리·빈 요소·상대 경로가 없는 경우
- **취약:** root 홈 또는 명령 검색 경로를 비관리자가 변경할 수 있거나 PATH에 현재 디렉터리·빈 요소·상대 경로가 있는 경우

### 조치 방법

root 로그인 환경 및 sudo 실행 환경에서 현재 디렉터리·빈 PATH 요소·비관리자 쓰기 가능 경로 제거

### 조치 시 영향

명령어 검색 순서 변경으로 운영 스크립트 및 사용자 설치 도구 실행에 영향이 있을 수 있으므로 필요한 명령의 절대 경로 확인

## 점검 및 조치 사례

### RHEL 10

1. root의 실제 홈 및 로그인 PATH 확인. sudo 실행 PATH도 별도로 확인

   ```bash command
   getent passwd root
   sudo -i sh -c 'printf "%s\n" "$PATH"'
   sudo printenv PATH
   ```

2. PATH의 `.`·상대 경로·빈 요소(`::`, 선행 또는 후행 `:`) 및 각 경로의 비관리자 쓰기 여부 확인

   ```bash command
   sudo -i sh -c 'printf "%s\n" "$PATH"' | tr ':' '\n'
   namei -l /usr/local/sbin /usr/local/bin /usr/sbin /usr/bin
   ```

3. 실제 root 시작 파일과 전역 시작 파일의 PATH 수정. 필요한 시스템 경로를 확인한 예시

   ```text configuration
   PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin
   export PATH
   ```

4. sudo의 별도 `secure_path`가 설정된 경우 `visudo`로 동일한 신뢰 경로 적용 후 구문 확인. root 홈과 시작 파일의 타 사용자 쓰기도 제거

   ```bash command
   sudo visudo
   sudo visudo -c
   ```

5. 새 root 로그인과 sudo 실행에서 PATH 및 운영 명령 정상 탐색 확인
