## 개요

### 점검 내용

홈 디렉터리 내의 환경변수 파일에 대한 소유자 및 접근 권한이 관리자 또는 해당 계정으로 설정 여부 점검

### 점검 목적

비인가자의 환경변수 조작으로 인한 보안 위험이 존재함

### 보안 위협

홈 디렉터리 내의 사용자 파일 및 사용자별 시스템 시작 파일 등과 같은 환경변수 파일의 접근 권한 설정이 적절하지 않을 경우, 비인가자가 환경변수 파일을 변조하여 정상 사용 중인 사용자의 서비스가 제한될 수 있는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 홈 디렉터리 환경변수 파일 소유자가 root 또는 해당 계정으로 지정되어 있고, 홈 디렉터리 환경변수 파일에 root 계정과 소유자만 쓰기 권한이 부여된 경우
- **취약:** 홈 디렉터리 환경변수 파일 소유자가 root 또는 해당 계정으로 지정되지 않거나, 홈 디렉터리 환경변수 파일에 root 계정과 소유자 외에 쓰기 권한이 부여된 경우

### 조치 방법

개인 시작 파일은 해당 사용자 또는 root가 관리하고 전역 환경 파일은 root 관리 및 비인가 쓰기 금지 설정

### 조치 시 영향

환경 설정은 새 로그인에 반영되며 시작 파일 실행 권한이나 공유 파일 접근을 일괄 변경하면 로그인·업무 환경에 영향이 있을 수 있음

## 점검 및 조치 사례

### RHEL 10

1. 사용자별 shell과 홈 확인 후 실제 시작 파일 조사. `USER`와 `/home/USER`는 점검 계정의 값으로 대체

   ```bash command
   getent passwd USER
   namei -l /home/USER/.profile /home/USER/.bashrc
   stat -c "%U %G %a %n" /etc/profile /etc/profile.d
   ```

2. 실제 존재하는 개인 시작 파일 및 포함 파일의 소유자·ACL 확인. Bash는 `.bash_profile`·`.bash_login`·`.profile` 우선순위와 `.bashrc` 포함 여부 확인

   ```bash command
   getfacl -p /home/USER/.profile /home/USER/.bashrc
   find /etc/profile.d -maxdepth 1 \( -type f -o -type l \) -ls
   ```

   `/etc/profile`의 포함 구문으로 실제 읽는 `.sh` 파일을 식별하고 각 파일의 심볼릭 링크 대상과 상위 경로 권한까지 점검. 역할별 파일을 읽은 뒤 사용자 시작 파일에서 재설정하는 값도 확인

3. 해당 계정이 소유해야 하는 개인 시작 파일의 소유자 및 쓰기 권한 조정

   ```bash command
   sudo chown USER /home/USER/.profile /home/USER/.bashrc
   sudo chmod go-w /home/USER/.profile /home/USER/.bashrc
   ```

4. 전역 파일 및 포함 스크립트는 root 관리로 복구하고 비인가 쓰기 ACL 제거. 다른 shell은 해당 shell의 실제 시작 파일에도 동일 기준 적용

5. 새 로그인에서 환경 변수와 업무 도구 정상 실행 확인
