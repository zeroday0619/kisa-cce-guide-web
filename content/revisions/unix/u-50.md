## 개요

### 점검 내용

Secondary Name Server로만 Zone 정보 전송 제한 여부 점검

### 점검 목적

DNS Zone Transfer 설정을 통해 비인가자에 대한 무단 접근을 방지하기 위함

### 보안 위협

Zone Transfer를 모든 사용자에게 허용할 경우, 비인가자에게 호스트 정보, 시스템 정보 등 중요 정보가 유출될 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** zone 전송이 비활성화되거나 승인된 secondary만 전송 가능한 경우
- **취약:** 비승인 주체가 zone 전송을 수행할 수 있는 경우

### 조치 방법

zone 전송을 비활성화하거나 승인 secondary로 제한

### 조치 시 영향

secondary 갱신 차단 시 zone 정보 만료 가능. serial 및 복제 상태 확인

## 점검 및 조치 사례

### RHEL 10

1. 실행 인수 및 포함 설정 파일 확인

   ```bash command
   systemctl cat named.service
   sudo named-checkconf /etc/named.conf
   ```

2. zone별 유효 접근 정책 확인

   options·view·zone과 include 파일의 `allow-transfer` 확인. secondary 목록과 전송 키의 승인 범위 대조

3. 불필요한 zone 전송 차단

   ```text configuration
   allow-transfer { none; };
   ```

4. 기존 zone에 정책 적용

   위 설정을 기존 options 또는 해당 zone에 반영하고 zone별 재정의 확인. 전송이 필요한 zone은 승인된 secondary의 TSIG key만 허용하도록 설정하고 비밀키 파일의 접근 권한 제한

5. 구문 검사 및 설정 적용

   ```bash command
   sudo named-checkconf /etc/named.conf
   sudo rndc reconfig
   sudo rndc status
   ```

6. 서비스 종속 동작 확인

   승인 secondary의 zone serial 및 복제 상태 확인. 전송이 불필요한 zone의 전송 정책과 서비스 로그 확인
