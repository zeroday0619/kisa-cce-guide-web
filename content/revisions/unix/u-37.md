## 개요

### 점검 내용

crontab 및 at 서비스 관련 파일의 권한 적절성 여부 점검

### 점검 목적

예약 작업 등록과 특권 작업 파일 변경을 승인 사용자로 제한하여 비인가자의 예약 실행을 방지하기 위함

### 보안 위협

일반 사용자가 crontab 및 at 서비스를 사용할 수 있을 경우, 고의 또는 실수로 불법적인 예약 파일 실행으로 시스템 피해를 일으킬 수 있는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 승인 사용자만 예약 작업을 등록할 수 있고 특권 작업 파일에 비인가 쓰기 권한이 없는 경우
- **취약:** 비인가자의 예약 작업 등록 또는 특권 작업 파일 변경이 가능한 경우

### 조치 방법

설치된 cron·at 구현의 허용 사용자 정책 적용 및 특권 예약 작업 파일 보호

### 조치 시 영향

예약된 백업·배치 작업 중단 가능. 실행 파일과 spool의 패키지 권한 일괄 변경 금지

## 점검 및 조치 사례

### RHEL 10

1. 예약 작업 구현 및 등록 작업 확인

   ```bash command
   rpm -q cronie at
   sudo crontab -l
   sudo atq
   systemctl list-timers --all
   sudo ls -ld /etc/crontab /etc/cron.* /etc/at.*
   ```

2. 허용 사용자 파일 설정

   설치된 `crontab(1)` 및 `at(1)` 매뉴얼의 접근 정책 확인 후 `/etc/cron.allow`와 `/etc/at.allow`에 root 및 승인 사용자만 한 줄씩 등록. 일반 사용자 전체 차단 시 root만 등록. allow 파일 우선순위와 deny 파일 부재 시 동작 확인

3. 예약 작업 파일의 비인가 쓰기 권한 확인

   ```bash command
   sudo find /etc/cron.d /etc/cron.daily /etc/cron.hourly /etc/cron.weekly /etc/cron.monthly -xdev -perm /022 -ls
   sudo stat -c '%U:%G %a %n' /etc/crontab /etc/cron.allow /etc/at.allow
   ```

4. 작업 파일 권한 및 기존 작업 정리

   root 작업 파일의 소유자를 root로 유지하고 그룹·기타 사용자 쓰기 권한 제거. 실행 스크립트의 실행 비트, spool 및 허용 파일의 구현별 필수 읽기 권한 보존. 각 사용자 crontab과 at 작업에서 승인되지 않은 기존 작업 별도 삭제

5. 접근 정책 및 작업 실행 확인

   승인 사용자 등록·수정 성공과 비승인 사용자 등록 거부 확인. systemd timer 및 사용자별 timer의 unit·실행 스크립트도 동일한 승인 범위로 점검. `systemctl cat NAME.timer NAME.service`와 `systemctl show NAME.timer NAME.service -p FragmentPath -p DropInPaths`에서 원본 unit과 `/etc/systemd/system/NAME.timer.d/*.conf`, `NAME.service.d/*.conf`의 병합 경로 확인. NAME은 실제 작업명으로 대체하고 사용자 timer는 해당 사용자의 `systemctl --user`로 확인. 역할별 변경은 `systemctl edit NAME.timer` 또는 `systemctl edit NAME.service`로 작성하고 `daemon-reload` 후 유효 설정 대조. 목록형 지시문은 누적 여부와 빈 값 초기화 규칙을 해당 지시문 기준으로 확인. allow·deny 변경만으로 기존 작업이 삭제되는 것으로 판단 금지
