## 개요

### 점검 내용

불필요한 world writable 파일 여부 점검

### 점검 목적

world writable 파일을 이용한 시스템 접근 및 악의적인 코드 실행을 방지하기 위함

### 보안 위협

시스템 파일과 같은 중요 파일에 world writable이 적용될 경우, 일반 사용자 및 비인가자가 해당 파일을 임의로 수정, 제거할 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** world writable 파일이 존재하지 않거나, 존재 시 설정 이유를 인지하고 있는 경우
- **취약:** world writable 파일이 존재하나 설정 이유를 인지하지 못하고 있는 경우

### 조치 방법

world writable 파일과 디렉터리를 조사하고 불필요한 전체 사용자 쓰기 권한 제거

### 조치 시 영향

공유 임시 디렉터리의 쓰기 권한을 일괄 제거하면 다중 사용자 작업에 장애가 발생할 수 있으므로 일반 파일과 sticky bit 공유 디렉터리를 구분

## 점검 및 조치 사례

### RHEL 10

1. 점검할 로컬 파일시스템 및 공유 경로 확인

   ```bash command
   findmnt -rn -o TARGET,FSTYPE,SOURCE
   ```

2. 마운트별 전체 사용자 쓰기 객체 검색. `/srv/data`는 승인된 점검 마운트로 대체

   ```bash command
   sudo find /srv/data -xdev -perm -0002 -ls
   ```

3. 파일 유형·업무 소유자·ACL과 공유 필요성 대조. `/tmp`·`/var/tmp` 및 애플리케이션 IPC 경로는 용도별로 분류

4. 불필요한 일반 파일의 other 쓰기 제거. 공유 데이터는 승인 그룹 또는 ACL로 필요한 사용자만 허용

   ```bash command
   sudo chmod o-w -- /srv/data/FILE
   getfacl -p /srv/data/FILE
   ```

5. 쓰기 권한 검색 재수행 및 업무 파일 생성 확인. 공유 디렉터리의 sticky bit와 보존 정책도 확인

   ```bash command
   stat -c "%U %G %a %n" /tmp /var/tmp
   ```
