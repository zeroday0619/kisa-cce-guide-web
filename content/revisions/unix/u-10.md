## 개요

### 점검 내용

`/etc/passwd` 파일 내 UID가 동일한 사용자 계정 존재 여부 점검

### 점검 목적

UID가 동일한 사용자 계정을 점검함으로써 타 사용자 계정 소유의 파일 및 디렉터리로의 악의적 접근 예방 및 침해사고 시 명확한 감사 추적을 하기 위함

### 보안 위협

중복된 UID가 존재할 경우, 시스템은 동일한 사용자로 인식하여 소유자의 권한이 중복되어 불필요한 권한이 부여되며 시스템 로그를 이용한 감사 추적 시 사용자가 구분되지 않는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 동일한 UID로 설정된 사용자 계정이 존재하지 않는 경우
- **취약:** 동일한 UID로 설정된 사용자 계정이 존재하는 경우

### 조치 방법

중복 UID 계정의 작업을 고유 UID와 전용 홈의 계정으로 분리하고 확인된 개별 데이터만 이전

### 조치 시 영향

동일 UID 및 공유 홈 파일은 계정명으로 소유자를 구분할 수 없으며 `usermod -u`가 홈 내 파일 소유권까지 변경할 수 있으므로 새 계정으로 분리 후 개별 이전

## 점검 및 조치 사례

### RHEL 10

1. NSS 및 로컬 파일의 중복 UID 확인

   ```bash command
   getent passwd | awk -F: '{count[$3]++; names[$3]=names[$3] " " $1} END {for (uid in count) if (count[uid] > 1) print uid, names[uid]}'
   cut -d: -f3 /etc/passwd | sort -n | uniq -d
   ```

2. 중복 계정의 홈 공유 여부·활성 세션·cron·서비스 및 NFS ID 매핑 확인. 중앙 계정 열거 제한과 컨테이너 UID 매핑은 호스트 계정과 구분

3. 중복 계정의 업무를 이전할 새 계정 생성. `NEW_USER`는 승인된 계정명으로 대체하고 업무 역할에 맞는 로그인 shell 선택

   ```bash command
   sudo useradd -m -U -s /bin/bash NEW_USER
   id NEW_USER
   ```

4. 소유자를 확인한 파일만 새 계정으로 이전하고 예약 작업·서비스 실행 사용자·원격 스토리지 매핑 수정. 기존 UID를 기준으로 한 일괄 chown 금지

5. 새 계정의 인증·업무 실행을 확인한 후 기존 중복 계정 사용을 종료하고 계정 관리 절차로 정리. 공유 홈과 기존 소유 파일은 유지한 상태에서 인계 목록과 대조

6. 중복 UID 검색 재수행 및 계정별 업무 데이터 접근 범위 확인
