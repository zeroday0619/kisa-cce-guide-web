## 개요

### 점검 내용

사용자 쉘에 대한 환경설정 파일에서 Session Timeout 설정 여부 점검

### 점검 목적

사용자의 고의 또는 실수로 시스템에 계정이 접속된 상태로 방치됨을 차단하기 위함

### 보안 위협

Session timeout 값이 설정되지 않을 경우, 유휴 시간 내 비인가자가 시스템에 접근하여 불필요한 내부정보를 노출할 위험이 존재함

### 참고

> **참고**
>
> Bash `TMOUT`은 프롬프트 입력 대기에 적용됨. SSH `ChannelTimeout`은 채널 트래픽 비활성을 측정하며 `ClientAliveInterval`은 연결 생존 확인이므로 사용자 입력 유휴 제한과 구분

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** Session Timeout이 600초(10분) 이하로 설정된 경우
- **취약:** Session Timeout이 600초(10분) 이하로 설정되지 않은 경우

### 조치 방법

대화형 관리 세션에 600초 이하의 유휴 제한을 설정하고 shell·SSH 채널별 적용 범위 확인

### 조치 시 영향

모니터링 및 장시간 무출력 작업의 세션이 종료될 수 있음. SSH 채널 종료가 모든 하위 프로세스 종료를 보장하지 않으므로 작업 실행 방식 확인 필요

## 점검 및 조치 사례

### RHEL 10

1. 로그인 shell 및 Bash 유휴 제한 확인

   ```bash command
   getent passwd USER
   printf '%s\n' "$SHELL" "${TMOUT-unset}"
   grep -Rns TMOUT /etc/profile /etc/profile.d /etc/bash*
   ```

2. Bash 로그인 사용자를 대상으로 `/etc/profile.d/session-timeout.sh`에 다음 설정 작성. 비로그인 대화형 shell은 실제로 읽는 Bash 시작 파일에도 정책 연결

   ```text configuration
   case $- in
       *i*)
           TMOUT=600
           readonly TMOUT
           export TMOUT
           ;;
   esac
   ```

3. SSH 채널 비활성 제한을 함께 적용하는 경우 유효 sshd 설정에 다음 값 반영. 현재 배포된 OpenSSH의 구문 검사로 옵션 지원 확인

   ```text configuration
   ChannelTimeout session=10m
   ```

4. 구문 확인 후 설정 반영 및 새 세션의 유휴 종료 확인

   ```bash command
   sudo /usr/sbin/sshd -t
   sudo /usr/sbin/sshd -T | grep channeltimeout
   sudo systemctl reload sshd.service
   ```

5. Bash 이외 shell, 콘솔 및 세션 관리 프로그램의 유휴 정책 확인. 편집기 실행 중 입력 대기와 장시간 무출력 작업은 각각 업무 영향 확인
