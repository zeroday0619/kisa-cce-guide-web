## 개요

### 점검 내용

로컬 비밀번호 저장에 안전한 해시 알고리즘 사용 여부 점검

### 점검 목적

안전한 비밀번호 암호화 알고리즘을 사용하여 사용자 계정정보를 보호하기 위함

### 보안 위협

취약한 비밀번호 암호화 알고리즘을 사용할 경우, 노출된 계정에 대해 비인가자가 암호 복호화 공격을 통해 비밀번호를 획득할 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 배포판이 지원하는 yescrypt 또는 승인된 SHA-512 crypt 등 안전한 비밀번호 해시를 사용하는 경우
- **취약:** DES·MD5 등 취약한 비밀번호 해시를 사용하는 경우

### 조치 방법

배포판이 지원하는 안전한 비밀번호 해시 정책을 적용하고 구형 해시 계정의 비밀번호 재설정

### 조치 시 영향

기존 비밀번호 재설정 시 연동 서비스에 영향이 있을 수 있음. 해시를 직접 소비하는 구형 애플리케이션의 호환성과 FIPS 요구사항 확인 필요

## 점검 및 조치 사례

### RHEL 10

1. 해시 전체를 출력하지 않고 사용 중인 알고리즘 식별자별 계정 수 확인. `1`은 MD5 계열, `6`은 SHA-512 crypt, `y`는 yescrypt 식별자

   ```bash command
   sudo awk -F: '$2 !~ /^[!*]/ && $2 != "" {n=split($2,a,"$"); if (n>2) count[a[2]]++; else count["legacy"]++} END {for (id in count) print id, count[id]}' /etc/shadow
   ```

2. 유효 password stack의 알고리즘 및 시스템 암호 정책 확인

   ```bash command
   sudo authselect current
   sudo authselect check
   grep -n pam_unix /etc/pam.d/system-auth /etc/pam.d/password-auth
   ```

3. DES·MD5 등 구형 알고리즘을 지정한 로컬 사용자 정의 PAM 설정을 제거하고 배포판이 지원하는 해시 정책 적용. RHEL의 생성 PAM 파일은 authselect profile에서 관리하며 FIPS 환경은 승인 알고리즘 적용

4. 기존 취약 해시 계정의 비밀번호를 재설정하여 새 정책으로 저장. `USER`는 변경 대상 계정으로 대체

   ```bash command
   sudo passwd USER
   ```

5. 알고리즘별 계정 수 재확인 및 정상 인증 확인. `login.defs` 또는 PAM 설정 변경만으로 기존 해시가 변환되지 않으므로 대상 계정별 전환 완료 확인
