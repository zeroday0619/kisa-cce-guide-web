## 개요

### 점검 내용

사용자 계정과 홈 디렉토리의 일치 여부 점검

### 점검 목적

`/home` 디렉토리 이외의 사용자의 홈 디렉토리 존재 여부를 점검하여 비인가자가 시스템 명령어의 무단 사용을 방지하기 위함

### 보안 위협

`/etc/passwd` 파일에 설정된 홈 디렉토리가 존재하지 않는 경우, 해당 계정으로 로그인 시 홈 디렉토리가 루트 디렉토리(`/`)로 할당되어 접근이 가능한 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 홈이 필요한 계정에 접근 가능한 홈이 있거나 승인된 자동 생성·마운트 경로가 정상 동작하는 경우
- **취약:** 홈이 필요한 계정의 홈이 없거나 접근할 수 없는 경우

### 조치 방법

홈이 필요한 대화형 계정에 승인된 홈 경로를 생성하거나 올바른 경로로 수정

### 조치 시 영향

네트워크 홈 장애 상태에서 로컬 홈을 만들면 복구 후 데이터가 가려질 수 있으므로 마운트 상태 확인 후 조치

## 점검 및 조치 사례

### RHEL 10

1. 대화형 계정의 홈 경로와 shell 확인

   ```bash command
   getent passwd | awk -F: '{print $1, $6, $7}'
   getent passwd USER
   ```

2. 실제 홈 디렉터리·자동 마운트 및 PAM 홈 생성 설정 확인. 네트워크 스토리지 장애를 로컬 홈 부재와 구분

   ```bash command
   ls -ld /home/USER
   findmnt -T /home/USER
   grep -RnsE "pam_mkhomedir|pam_oddjob_mkhomedir" /etc/pam.d
   ```

3. 로컬 대화형 계정의 홈 누락이 확인된 경우 승인 경로에 생성. `USER`·`GROUP`·경로는 해당 계정 정보로 대체하며 존재하는 디렉터리에는 재적용하지 않음

   ```bash command
   sudo install -d -m 0700 -o USER -g GROUP /home/USER
   sudo restorecon -RF /home/USER
   ```

4. passwd에 등록된 경로가 잘못된 경우 지원 도구로 경로 수정. 기존 데이터 이동이 필요한 경우 별도 인계 후 처리

   ```bash command
   sudo usermod -d /home/USER USER
   ```

5. 새 로그인에서 홈 이동·파일 생성·로그아웃 확인. `/nonexistent` 등 서비스 계정의 의도된 비로그인 홈은 생성 대상에서 제외
