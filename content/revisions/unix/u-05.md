## 개요

### 점검 내용

사용자 계정 정보가 저장된 파일(`/etc/passwd`, `/etc/shadow` 등)에 root(UID=0) 계정과 동일한 UID를 가진 계정이 존재 여부 점검

### 점검 목적

root 계정과 동일한 UID가 존재하는지 점검하여 root 권한이 일반 사용자 계정이나 비인가자의 접근 위협에 안전하게 보호되고 있는지 확인하기 위함

### 보안 위협

root 계정과 동일한 UID가 설정되어 있는 일반 사용자 계정도 root 권한을 부여받아 관리자가 실행할 수 있는 모든 작업이 가능한 위험이 존재함(서비스 시작, 중지, 재부팅, root 권한 파일 편집 등). root 계정과 동일한 UID를 사용하므로 사용자 감사 추적 시 어려움 발생 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** root 계정과 동일한 UID를 갖는 계정이 존재하지 않는 경우
- **취약:** root 계정과 동일한 UID를 갖는 계정이 존재하는 경우

### 조치 방법

root 이외 UID 0 계정을 고유 UID의 새 개인 관리 계정으로 이전하고 필요한 sudo 권한만 부여

### 조치 시 영향

UID 0 계정의 홈은 root와 공유될 수 있으므로 기존 계정에 `usermod -u`를 적용하지 않음. 개별 데이터 및 작업 이전 후 중복 계정 정리 필요

## 점검 및 조치 사례

### RHEL 10

1. 로컬 및 NSS 계정 중 UID 0 계정과 홈 확인

   ```bash command
   getent passwd | awk -F: '$3 == 0 {print $1, $3, $6, $7}'
   awk -F: '$3 == 0 {print $1, $3, $6}' /etc/passwd
   ```

2. 중복 계정의 업무 소유자·SSH 인증·예약 작업·서비스 의존성 확인. 중앙 계정 열거가 제한된 경우 인증 공급자에서 UID 중복 조회

3. 고유 UID와 전용 홈을 가진 새 관리 계정 생성. `NEW_USER`는 승인된 새 계정명으로 대체

   ```bash command
   sudo useradd -m -U -s /bin/bash NEW_USER
   id NEW_USER
   ```

4. 새 계정의 SSH 인증 및 필요한 sudo 권한을 별도 설정하고 정상 로그인·권한 상승 확인. sudo 정책 변경은 `visudo`로 관리

   ```bash command
   sudo visudo
   sudo visudo -c
   ```

5. 업무 소유가 확인된 개별 파일·cron·자동화만 새 계정으로 이전. UID 0 파일은 root 파일과 구분할 수 없으므로 UID 기준의 일괄 소유권 변경 금지

6. 중복 이름을 사용하는 인증과 작업 제거 후 계정 관리 절차로 중복 항목 정리. root 항목·root 홈·root 소유 파일을 유지하고 UID 0 계정 재조회로 root만 남았는지 확인
