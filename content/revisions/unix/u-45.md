## 개요

### 점검 내용

취약한 버전의 메일 서비스 이용 여부 점검

### 점검 목적

메일 서비스 사용 목적 검토 및 취약점이 없는 버전의 사용 유무 점검으로 최적화된 메일 서비스의 운영하기 위함

### 보안 위협

취약점이 발견된 메일 버전의 경우 버퍼 오버플로우(Buffer Overflow) 공격에 의한 시스템 권한 획득 및 주요 정보 노출의 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 메일 서비스를 사용하지 않거나 지원되는 패키지의 필요한 보안 수정이 적용된 경우
- **취약:** 메일 서비스가 지원 종료 상태이거나 필요한 보안 수정이 적용되지 않은 경우

### 조치 방법

지원되는 저장소의 메일 서비스 보안 업데이트 적용 및 불필요한 서버 비활성화

### 조치 시 영향

메일 큐 처리 지연 및 TLS·필터 연동 영향 가능. 정상 송수신과 수정된 프로세스 실행 확인

## 점검 및 조치 사례

### RHEL 10

1. 설치 구현 및 배포판 패키지 버전 확인

   ```bash command
   rpm -qa | grep -E "^(postfix|sendmail|exim)"
   ```

2. 저장소 및 보안 업데이트 확인

   ```bash command
   sudo dnf repolist
   sudo dnf updateinfo list --security
   ```

3. 해당 패키지 보안 권고 대조

   배포판 보안 권고에서 설치 패키지의 수정 버전과 적용 기한 확인. upstream 버전 문자열 대신 배포판의 보안 수정 포함 여부로 판단. 자체 빌드 및 외부 저장소 패키지는 공급자의 지원 경로와 수정 내역 확인

4. 사용 중인 패키지 업데이트

   ```bash command
   sudo dnf upgrade --security postfix
   ```

5. 수정된 프로세스 적용 및 서비스 확인

   Postfix 예시의 패키지명을 실제 사용 중인 MTA로 대체. 큐 백업·필터 연동 확인 후 해당 서비스 재시작 및 정상 송수신 확인

### Ubuntu 26.04 LTS

1. 설치 구현 및 배포판 패키지 버전 확인

   ```bash command
   dpkg-query -W postfix exim4-base sendmail-bin
   ```

2. 저장소 및 보안 업데이트 확인

   ```bash command
   sudo apt update
   apt list --upgradable
   apt-mark showhold
   ```

3. 해당 패키지 보안 권고 대조

   배포판 보안 권고에서 설치 패키지의 수정 버전과 적용 기한 확인. upstream 버전 문자열 대신 배포판의 보안 수정 포함 여부로 판단. 자체 빌드 및 외부 저장소 패키지는 공급자의 지원 경로와 수정 내역 확인

4. 사용 중인 패키지 업데이트

   ```bash command
   sudo apt install --only-upgrade postfix
   ```

5. 수정된 프로세스 적용 및 서비스 확인

   Postfix 예시의 패키지명을 실제 사용 중인 MTA로 대체. 큐 백업·필터 연동 확인 후 해당 서비스 재시작 및 정상 송수신 확인
