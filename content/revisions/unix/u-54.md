## 개요

### 점검 내용

암호화되지 않은 FTP 서비스 비활성화 여부 점검

### 점검 목적

암호화되지 않은 FTP 서비스를 비활성화함으로써 계정 및 중요 정보 유출 방지하기 위함

### 보안 위협

암호화되지 않은 FTP 서비스를 사용할 경우, 데이터가 평문으로 전송되어 비인가자가 스니핑을 통해 계정 및 중요 정보를 외부로 유출할 위험이 존재함

### 참고

> **참고**
>
> SFTP는 SSH 기반 파일 전송으로 FTPS와 다른 프로토콜. TLS 지원 설정만으로 인증 및 데이터 채널 암호화가 강제되는 것은 아님

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 암호화되지 않은 FTP 서비스가 비활성화된 경우
- **취약:** 암호화되지 않은 FTP 서비스가 활성화된 경우

### 조치 방법

평문 FTP 비활성화 및 SFTP 전환 또는 FTPS 인증·데이터 채널 암호화 강제

### 조치 시 영향

기존 FTP 자동화와 SFTP는 호환되지 않음. FTPS passive 포트, 인증서 갱신 및 파일 권한 확인

## 점검 및 조치 사례

### RHEL 10

1. FTP 구현 및 실제 설정 경로 확인

   ```bash command
   rpm -q vsftpd
   systemctl cat vsftpd.service
   sudo ss -lntp
   ```

2. 설정 변경 전 기존 항목 확인

   `/etc/vsftpd/vsftpd.conf` 및 daemon 실행 인수에서 실제 설정 경로 확인. 중복 설정과 별도 인스턴스를 포함하여 로그인·데이터 채널의 TLS 강제 여부와 실제 클라이언트 암호화 설정 확인

3. vsftpd 설정 수정

   ```text configuration
   anonymous_enable=NO
   ssl_enable=YES
   force_local_logins_ssl=YES
   force_local_data_ssl=YES
   rsa_cert_file=/etc/ssl/certs/ftp-server.pem
   rsa_private_key_file=/etc/ssl/private/ftp-server.key
   ```

4. 설정 경로 및 운영 조건 반영

   `/etc/vsftpd/vsftpd.conf`의 해당 항목 수정. 예시는 FTPS 유지 시 적용. 인증서·키 경로는 실제 유효한 서버 인증서와 비공개 키로 대체하고 daemon의 읽기 권한 및 키의 비인가 접근 차단 확인. 지원 암호 정책과 클라이언트 인증서 신뢰 확인. SFTP로 전환한 경우 전송 확인 후 vsftpd 서비스 비활성화. 평문 로그인 및 평문 데이터 채널 거부와 암호화된 정상 전송 확인

5. FTPS 유지 시에만 vsftpd 재시작 및 실행 상태 확인

   SFTP 전환으로 비활성화한 경우 아래 재시작 명령 생략 및 비활성 상태 유지

   ```bash command
   sudo systemctl restart vsftpd.service
   systemctl status vsftpd.service
   sudo journalctl -u vsftpd.service -n 30 --no-pager
   ```
