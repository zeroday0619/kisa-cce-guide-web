## 개요

### 점검 내용

`$HOME/.rhosts` 및 `/etc/hosts.equiv` 파일에 대해 적절한 소유자 및 접근 권한 설정 여부 점검

### 점검 목적

r-command를 통한 별도의 인증 없는 관리자 권한 원격 접속을 차단하기 위함

### 보안 위협

r-command(rlogin, rsh 등)에 보안 설정이 적용되지 않을 경우, 원격지의 공격자가 관리자 권한으로 목표 시스템상 임의의 명령을 수행시킬 수 있으며, 명령어 원격실행을 통해 중요 정보유출 및 시스템 장애를 유발 또는 공격자의 백도어 등으로도 활용될 수 있는 위험이 존재함. 해당 파일은 r-command 서비스의 접근통제에 관련된 파일이며, 권한 설정이 부적절한 경우 r-command 서비스 사용 권한을 임의로 등록하여 무단 사용 위험이 존재함

### 참고

> **참고**
>
> 개정판은 신뢰 파일 권한만 조정하여 r 계열 인증을 계속 사용하는 원본의 예외 대신 암호화된 개별 인증으로 전환하는 기준 적용

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** rlogin·rsh·rexec 서비스와 호스트 신뢰 인증을 사용하지 않는 경우
- **취약:** rlogin·rsh·rexec 또는 `.rhosts`·`hosts.equiv` 기반 신뢰 인증을 사용하는 경우

### 조치 방법

호스트 신뢰 기반 r 계열 원격 인증을 SSH로 전환하고 불필요한 서비스 및 신뢰 파일 제거

### 조치 시 영향

r 계열 인증을 사용하는 백업·원격 배치가 중단될 수 있으므로 SSH 이전 및 실제 작업 성공 확인 후 기존 경로 제거

## 점검 및 조치 사례

### RHEL 10

1. 호스트 신뢰 파일 및 r 계열 서버 설치·활성 상태 확인

   ```bash command
   rpm -qa | grep -E 'rsh|rlogin|inetd'
   systemctl list-sockets --all
   sudo ss -lntup
   ```

2. 실제 사용자 홈 및 `/etc/hosts.equiv` 조사. `/home/USER`는 NSS에서 확인한 홈으로 대체

   ```bash command
   getent passwd USER
   sudo ls -l /etc/hosts.equiv /home/USER/.rhosts
   grep -Rns pam_rhosts /etc/pam.d
   ```

3. r 계열 접속을 사용하는 백업·배치를 개인 또는 전용 계정의 SSH 인증으로 이전. 새 인증 경로의 작업 성공 확인

4. 발견된 r 서비스와 socket 중지·비활성화. `UNIT`은 실제 서버 또는 socket 이름으로 대체하고 inetd 제공 서비스는 해당 daemon 설정에서 제거

   ```bash command
   sudo systemctl disable --now UNIT
   ```

5. 신뢰 파일을 보존 정책에 따라 보호된 위치로 이관 후 활성 경로에서 제거. r 계열 listener와 PAM 신뢰 인증 경로의 부재 확인
