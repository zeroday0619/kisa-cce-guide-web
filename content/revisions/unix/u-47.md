## 개요

### 점검 내용

SMTP 서버의 릴레이 기능 제한 여부 점검

### 점검 목적

스팸 메일 서버로의 악용 방지 및 서버 과부하를 방지하기 위함

### 보안 위협

SMTP 서버의 릴레이 기능을 제한하지 않을 경우, 악의적인 사용 목적을 가진 사용자들이 스팸 메일 서버로 사용하거나 DoS 공격의 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 릴레이 제한이 설정된 경우
- **취약:** 릴레이 제한이 설정되어 있지 않은 경우

### 조치 방법

메일 릴레이를 승인 네트워크 또는 인증 사용자로 제한하고 비인가 목적지 거부

### 조치 시 영향

정상 외부 발신 및 중계 업무 중단 가능. 수신 도메인과 제출 사용자 범위 확인

## 점검 및 조치 사례

### RHEL 10

1. Postfix 유효 릴레이 정책 및 서비스별 설정 확인

   ```bash command
   sudo postconf mynetworks smtpd_relay_restrictions mydestination relay_domains
   sudo postconf -M
   sudo postconf -P
   ```

2. 비인가 릴레이 목적지 거부 설정

   ```text configuration
   mynetworks = 127.0.0.0/8 [::1]/128
   smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, reject_unauth_destination
   ```

3. 업무상 허용 범위 반영

   `/etc/postfix/main.cf`의 기존 설정 수정. 예시는 로컬 호스트만 신뢰하는 구성으로 승인된 업무 서버가 필요한 경우 해당 주소만 추가. `mydestination`, `relay_domains`는 실제 수신·중계 도메인으로 한정. `master.cf`의 서비스별 override 및 제출 포트 인증·TLS 설정 함께 확인

4. 구문 검사 및 적용

   ```bash command
   sudo postfix check
   sudo postfix reload
   sudo postconf smtpd_relay_restrictions mynetworks
   ```

5. 허용 범위 및 정상 배달 확인

   자체 시험 계정과 관리하는 도메인으로 승인 발신·수신 경로 확인. 비승인 출발지의 외부 도메인 중계가 허용되지 않는지 메일 로그와 정책 결과 확인. 다른 MTA는 해당 릴레이 ACL 사용
