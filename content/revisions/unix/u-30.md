## 개요

### 점검 내용

시스템 UMASK 값이 022 이상 설정 여부 점검

### 점검 목적

잘못 설정된 UMASK 값으로 인해 신규 파일에 대한 권한이 과도하게 부여되는 것을 방지하기 위함

### 보안 위협

잘못 설정된 UMASK로 인해 파일 및 디렉터리 생성 시 과도한 권한이 부여되어 무단 액세스 및 데이터 유출의 위험이 존재함

### 참고

> **참고**
>
> umask는 숫자의 대소가 아닌 비트별 제한으로 판단. 022·027·077은 그룹·other 쓰기를 제한하며 디렉터리 기본 ACL이 있으면 실제 생성 권한도 확인

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 새 파일의 그룹·other 쓰기를 제거하는 022 또는 이에 필요한 제한 비트를 포함한 마스크를 적용한 경우
- **취약:** 새 파일에 불필요한 그룹·other 쓰기 권한이 생성되는 경우

### 조치 방법

로그인 shell 및 서비스별 생성 마스크에 그룹·other 쓰기 제한을 설정하고 실제 생성 결과 확인

### 조치 시 영향

umask 변경은 기존 파일에 소급되지 않음. 077 등 강한 제한은 공동 작업에 영향이 있으므로 공유 그룹·ACL 요구사항과 함께 적용

## 점검 및 조치 사례

### RHEL 10

1. 사용자 로그인 shell·PAM 및 대상 서비스의 생성 마스크 확인. `UNIT.service`는 실제 서비스로 대체

   ```bash command
   umask
   grep -Rns pam_umask /etc/pam.d
   systemctl show UNIT.service -p UMask
   ```

2. `/etc/profile`에서 `/etc/profile.d/*.sh`를 읽는 로그인 shell은 `/etc/profile.d/60-local-umask.sh`에 역할별 설정 작성. 비로그인 shell과 사용자 시작 파일의 후속 재설정도 확인. 예시는 그룹·other 쓰기를 제거하는 기준이며 기존의 더 제한적인 마스크는 유지

   ```text configuration
   umask 022
   ```

3. systemd 서비스는 `/etc/systemd/system/UNIT.service.d/60-local-umask.conf`에 다음 개별 drop-in 작성. 패키지 unit을 보존하고 기존 drop-in의 UMask 중복 및 파일명 순서 확인

   ```text configuration
   [Service]
   UMask=0027
   ```

4. unit 재읽기 후 유지보수 시간에 대상 서비스 재시작. 개인 로그인은 새 세션에서 마스크 확인

   ```bash command
   sudo systemctl daemon-reload
   sudo systemctl restart UNIT.service
   systemctl show UNIT.service -p UMask
   ```

5. 업무 디렉터리의 기본 ACL 및 실제 생성 파일 모드 확인. 기본 ACL·애플리케이션 chmod가 있으면 생성 결과를 기준으로 판단

   ```bash command
   getfacl -p /srv/data
   stat -c "%a %n" /srv/data/TEST_FILE
   ```
