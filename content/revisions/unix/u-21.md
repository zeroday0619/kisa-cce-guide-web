## 개요

### 점검 내용

`/etc/(r)syslog.conf` 파일 권한 적절성 여부 점검

### 점검 목적

`/etc/(r)syslog.conf` 파일의 권한 적절성을 점검하여, 비인가자의 임의적인 `/etc/(r)syslog.conf` 파일 변조를 방지하기 위함

### 보안 위협

`/etc/(r)syslog.conf` 파일의 설정 내용을 참조하여 로그의 저장 위치가 노출되며 로그를 기록하지 않도록 설정하거나 대량의 로그를 기록하게 하여 시스템 과부하를 유도할 수 있는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 사용 중인 로그 수집기 설정을 root가 관리하고 비인가 쓰기 및 비밀정보의 불필요한 읽기를 차단한 경우
- **취약:** 로그 수집기 설정에 비인가 쓰기 또는 비밀정보의 불필요한 읽기 권한이 부여된 경우

### 조치 방법

실제 로그 수집기의 설정과 포함 파일을 root 관리로 유지하고 비인가 쓰기 제거

### 조치 시 영향

로그 수집기 재시작 또는 설정 읽기 실패 시 수집 공백이 발생할 수 있으므로 구문 및 새 로그 수신 확인 필요

## 점검 및 조치 사례

### RHEL 10

1. 실제 로그 수집 서비스와 설정 파일 확인. rsyslog 미설치 시 journald 설정 대상으로 진행

   ```bash command
   systemctl status systemd-journald.service rsyslog.service
   systemd-analyze cat-config systemd/journald.conf
   ```

2. journald 및 사용 중인 rsyslog 설정·포함 파일의 소유자·모드·ACL 확인

   ```bash command
   stat -c "%U %G %a %n" /etc/systemd/journald.conf
   getfacl -p /etc/systemd/journald.conf
   ```

3. rsyslog 설정이 존재하는 경우 root 소유 및 제한된 읽기 권한 적용. 포함 파일도 동일하게 점검하며 실행 주체에 필요한 읽기는 유지

   ```bash command
   sudo chown root:root /etc/rsyslog.conf
   sudo chmod 0640 /etc/rsyslog.conf
   sudo rsyslogd -N1
   ```

4. journald 설정과 drop-in은 root 소유 및 비인가 쓰기 제거. 비밀키·인증정보를 포함한 전송 설정은 별도 제한 파일로 관리

5. 수정한 수집기 설정의 유효성 및 새 로그 수신 확인. 설정 내용 변경 시 해당 수집기만 유지보수 시간에 재시작

   ```bash command
   logger -t security-check "logging configuration check"
   sudo journalctl -t security-check -n 5 --no-pager
   ```
