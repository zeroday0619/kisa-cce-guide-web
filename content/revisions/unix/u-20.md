## 개요

### 점검 내용

`/etc/(x)inetd.conf` 파일 권한 적절성 여부 점검

### 점검 목적

`/etc/(x)inetd.conf` 파일을 관리자만 제어하여 비인가자들의 임의적인 파일 변조를 방지하기 위함

### 보안 위협

`/etc/(x)inetd.conf` 파일에 소유자 외 쓰기 권한이 부여된 경우, 일반 사용자 권한으로 해당 파일에 등록된 서비스를 변조하거나 악의적인 프로그램(서비스)을 등록할 수 있는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** inetd 계열을 사용하지 않거나 설정을 root 소유·0600으로 보호하고 대체 socket 설정의 비인가 쓰기를 차단한 경우
- **취약:** 사용 중인 inetd 설정 또는 socket 활성화 설정을 비관리자가 변경할 수 있는 경우

### 조치 방법

사용 중인 inetd 설정 및 systemd socket 활성화 설정의 소유자·권한을 보호하고 불필요한 서비스 비활성화

### 조치 시 영향

socket 또는 super-server 중지 시 연결된 서비스가 함께 중단될 수 있으므로 의존 서비스 확인 필요

## 점검 및 조치 사례

### RHEL 10

1. inetd 계열 패키지 및 socket 활성화 현황 확인

   ```bash command
   rpm -qa | grep -E 'inetd|xinetd'
   systemctl list-sockets --all
   ```

2. 활성 socket의 실제 unit·포함 파일 및 실행 서비스 확인. `UNIT.socket`은 발견된 socket으로 대체

   ```bash command
   systemctl cat UNIT.socket
   systemctl show UNIT.socket -p FragmentPath -p DropInPaths -p Triggers
   ```

3. 사용 중인 inetd 설정만 root 소유 및 0600으로 보호. `/etc/inetd.conf` 예시이며 xinetd는 실제 설정과 포함 파일에 동일 기준 적용. 미설치 환경에 빈 설정 파일 생성 불필요

   ```bash command
   sudo stat -c "%U %G %a %n" /etc/inetd.conf
   sudo chown root:root /etc/inetd.conf
   sudo chmod 0600 /etc/inetd.conf
   ```

4. systemd socket unit과 drop-in은 root 소유 및 비인가 쓰기 금지 확인. 패키지 unit은 패키지에서 복구하고 로컬 변경은 `/etc/systemd/system/UNIT.socket.d/60-local-listen.conf` 등 역할별 `.conf`에 유지. `DropInPaths`가 가리키는 모든 파일과 상위 디렉터리 권한 확인

5. 불필요한 서비스의 socket과 실행 서비스를 함께 비활성화한 후 listening 현황 재확인

   ```bash command
   sudo ss -lntup
   systemctl list-sockets --all
   ```
