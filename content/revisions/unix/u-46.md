## 개요

### 점검 내용

메일 서비스 및 queue 관리 권한의 승인 사용자 제한 여부 점검

### 점검 목적

비인가자의 메일 서비스 제어와 queue 변경을 차단하여 메일 처리 장애를 방지하기 위함

### 보안 위협

일반 사용자에게 메일 daemon 제어 또는 queue 변경 권한이 부여된 경우, 메일 삭제 및 서비스 중단의 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 비인가자의 메일 daemon 제어 및 queue 변경이 차단된 경우
- **취약:** 비인가자가 메일 daemon을 제어하거나 queue를 변경할 수 있는 경우

### 조치 방법

메일 daemon 제어 및 queue 관리 권한을 승인 관리자에게 제한

### 조치 시 영향

메일 제출용 helper의 임의 권한 변경 시 알림 전송 실패 가능. 정상 제출 기능 보존

## 점검 및 조치 사례

### RHEL 10

1. 메일 구현 및 관리 서비스 확인

   ```bash command
   rpm -q postfix sendmail exim
   systemctl cat postfix.service
   sudo postconf queue_directory mail_owner setgid_group
   ```

2. 관리 명령 및 queue 권한 확인

   ```bash command
   sudo stat -c '%U:%G %a %n' /usr/sbin/postfix /usr/sbin/postsuper /var/spool/postfix
   sudo visudo -c
   ```

3. 비인가 관리 권한 제거

   `/etc/sudoers`와 포함 파일에서 승인되지 않은 postfix·postsuper·서비스 제어 권한 제거. queue 경로의 사용자·그룹·ACL을 설치 패키지 기준으로 복원하고 일반 사용자 쓰기 권한 제거. 사용자 메일 제출용 postdrop 등의 패키지 특권은 보존

4. Postfix 구성 권한 검사

   ```bash command
   sudo postfix check
   ```

5. 관리 제한 및 정상 제출 확인

   비승인 사용자에게 queue 삭제·강제 관리 및 daemon 제어 권한이 없는지 확인. 애플리케이션의 정상 메일 제출 확인. Exim·Sendmail은 해당 패키지의 관리 명령 및 queue 권한으로 동일 범위 점검
