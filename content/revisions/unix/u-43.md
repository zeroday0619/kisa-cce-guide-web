## 개요

### 점검 내용

NIS·NIS+ 사용 여부 및 지원되는 인증 경로 전환 여부 점검

### 점검 목적

구형 네트워크 계정 정보 공유를 제거하고 보호된 인증 경로를 사용하여 계정 정보 유출을 방지하기 위함

### 보안 위협

보호가 미흡한 NIS 기반 계정 정보가 노출될 경우, 비인가자의 사용자 정보 수집 및 계정 탈취 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** NIS·NIS+를 사용하지 않고 지원되는 인증 경로를 사용하는 경우
- **취약:** NIS·NIS+에 계정 조회 또는 인증을 의존하는 경우

### 조치 방법

지원되는 중앙 인증으로 전환 후 NIS·NIS+ 의존성 제거

### 조치 시 영향

계정 조회 및 로그인 실패 가능. 복구 계정과 단계별 전환 절차 확보

## 점검 및 조치 사례

### RHEL 10

1. NIS 조회 및 서비스 사용 여부 확인

   ```bash command
   grep -nE 'nis|nisplus|compat' /etc/nsswitch.conf
   systemctl list-unit-files | grep -E 'ypbind|ypserv|yppasswdd|ypxfrd'
   authselect current
   authselect check
   ```

2. 중앙 인증 전환 및 계정 연속성 확인

   지원되는 IdM·AD·LDAP/Kerberos 연동으로 계정·그룹·sudo·홈 디렉터리 이전. 로컬 복구 계정 및 기존 관리 세션 유지. NIS+를 신규 대체 인증 방식으로 도입하지 않도록 설정

3. 인증 설정 관리 경로에 따른 NIS 조회 제거

   현재 authselect profile과 feature를 보존하면서 승인된 인증 profile로 변경. 생성된 system-auth·password-auth 직접 덮어쓰기 금지

4. NIS 서비스 비활성화 및 인증 확인

   전환 완료 후 발견된 ypbind·ypserv 관련 unit을 `systemctl disable --now UNIT`으로 비활성화. `getent passwd USER`, `id USER`에서 전환 사용자 조회와 실제 로그인·권한 상승 확인. USER는 승인된 시험 계정으로 대체

### Ubuntu 26.04 LTS

1. NIS 조회 및 서비스 사용 여부 확인

   ```bash command
   grep -nE 'nis|nisplus|compat' /etc/nsswitch.conf
   systemctl list-unit-files | grep -E 'ypbind|ypserv|yppasswdd|ypxfrd'
   grep -R -nE 'pam_(unix|sss|ldap)' /etc/pam.d
   ```

2. 중앙 인증 전환 및 계정 연속성 확인

   지원되는 IdM·AD·LDAP/Kerberos 연동으로 계정·그룹·sudo·홈 디렉터리 이전. 로컬 복구 계정 및 기존 관리 세션 유지. NIS+를 신규 대체 인증 방식으로 도입하지 않도록 설정

3. 인증 설정 관리 경로에 따른 NIS 조회 제거

   설치된 PAM profile을 pam-auth-update로 관리하고 nsswitch.conf의 NIS 조회 항목만 제거. 기존 files·systemd·sss 등 필요한 조회 경로 보존

4. NIS 서비스 비활성화 및 인증 확인

   전환 완료 후 발견된 ypbind·ypserv 관련 unit을 `systemctl disable --now UNIT`으로 비활성화. `getent passwd USER`, `id USER`에서 전환 사용자 조회와 실제 로그인·권한 상승 확인. USER는 승인된 시험 계정으로 대체
