## 개요

### 점검 내용

r-command 서비스 비활성화 여부 점검

### 점검 목적

r 계열 원격 접속의 평문 전송과 호스트 신뢰에 의존하는 인증을 제거하여 비인가자의 원격 접근을 방지하기 위함

### 보안 위협

rsh, rlogin의 호스트 신뢰 설정 또는 r 계열 서비스의 평문 인증정보가 악용될 경우, 비인가자가 원격 명령을 실행하거나 계정을 탈취할 위험이 존재함

### 참고

> **참고**
>
> UDP 514의 syslog와 TCP 514의 rsh를 구분. rsync는 rsh·rlogin·rexec과 별도 서비스로 점검

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 불필요한 r 계열 서비스가 비활성화된 경우
- **취약:** 불필요한 r 계열 서비스가 활성화된 경우

### 조치 방법

rsh, rlogin, rexec 서버를 SSH 기반 관리로 전환 후 비활성화 설정

### 조치 시 영향

백업·클러스터링 작업 중단 가능. SSH 전환 후 정상 백업 및 복구 확인

## 점검 및 조치 사례

### RHEL 10

1. 설치된 서버 패키지 및 서비스 활성화 경로 확인

   ```bash command
   rpm -qa | grep -Ei 'rsh|rlogin|rexec'
   systemctl list-unit-files | grep -Ei 'rsh|rlogin|rexec'
   systemctl list-sockets --all
   sudo ss -lntup
   ```

2. 표준 포트 및 별도 실행 설정 확인

   TCP 512, 513, 514의 수신 프로세스와 실행 인수 확인. `/etc/inetd.conf`, `/etc/xinetd.d/`가 존재하는 경우 해당 서비스 항목 확인. 패키지 미설치 및 포트 부재만으로 비활성 여부를 판단하지 않고 사용자 지정 서비스도 확인

3. 불필요한 서버 활성화 설정 제거

   확인된 서비스와 socket 이름을 지정하여 `systemctl disable --now UNIT` 실행. `UNIT`은 실제 해당 unit 이름으로 대체. inetd는 해당 항목 주석 처리, xinetd는 해당 항목의 `disable = yes` 설정 후 사용 중인 관리자 서비스 재시작. 다른 서비스를 함께 제공하는 inetd 전체 중지 금지

4. 서비스 및 socket 재활성화 여부 확인

   ```bash command
   systemctl list-units --all | grep -Ei 'rsh|rlogin|rexec'
   systemctl list-sockets --all
   sudo ss -lntup
   ```
