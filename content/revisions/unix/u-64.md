## 개요

### 점검 내용

시스템에서 최신 패치가 적용 여부 점검

### 점검 목적

주기적인 패치 적용을 통해 시스템 안정성 및 보안성을 확보하기 위함

### 보안 위협

최신 보안패치가 적용되지 않을 경우, 이미 알려진 취약점을 통하여 공격자에 의해 시스템 침해사고 발생할 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 패치 적용 정책을 수립하여 주기적으로 패치 관리를 하고 있으며, 패치 관련 내용을 확인하고 적용하였을 경우
- **취약:** 패치 적용 정책을 수립하지 않고 주기적으로 패치 관리를 하지 않거나, 패치 관련 내용을 확인하지 않고 적용하지 않고 있는 경우

### 조치 방법

배포판 보안 권고에 따른 주기적 패치 적용 및 서비스 재시작·재부팅 관리

### 조치 시 영향

서비스 재시작과 커널 변경으로 업무 중단 가능. 변경 시간 및 복구 계획 확인

## 점검 및 조치 사례

### RHEL 10

1. 배포판 및 업데이트 공급 경로 확인

   ```bash command
   cat /etc/os-release
   sudo dnf repolist
   sudo dnf updateinfo list --security
   ```

2. 보안 권고 및 패치 적용 계획 확인

   설치 패키지의 배포판 보안 권고, 지원 범위와 수정 버전 대조. 적용 기한·유예 사유·복구 계획 확인. 외부 저장소·자체 설치 소프트웨어 및 컨테이너 이미지는 별도 공급 경로로 점검

3. 업데이트 사전 확인 및 적용

   ```bash command
   sudo dnf upgrade --security --assumeno
   sudo dnf upgrade --security
   ```

4. 보류 및 추가 변경 패키지 확인

   사전 확인에서 제거·신규 설치·보류 항목의 업무 영향 검토. 보류된 보안 수정은 패키지별 종속성 해결 및 승인된 변경 계획에 따라 적용. 자동 업데이트는 조직의 재시작·유예 정책과 일치하도록 운영

5. 실행 커널 및 장애 서비스 확인

   ```bash command
   uname -r
   systemctl --failed
   sudo dnf updateinfo list --security
   ```

6. 재시작 및 적용 증거 확인

   수정 전 라이브러리를 사용하는 서비스 재시작과 커널 업데이트의 재부팅 반영 확인. 배포판 도구가 안내하는 재부팅 요구 및 업무 기능 점검. 패키지 설치 성공만으로 실행 중 프로세스까지 수정된 것으로 판단 금지

### Ubuntu 26.04 LTS

1. 배포판 및 업데이트 공급 경로 확인

   ```bash command
   cat /etc/os-release
   sudo apt update
   apt-cache policy
   apt list --upgradable
   apt-mark showhold
   ```

2. 보안 권고 및 패치 적용 계획 확인

   설치 패키지의 배포판 보안 권고, 지원 범위와 수정 버전 대조. 적용 기한·유예 사유·복구 계획 확인. 외부 저장소·자체 설치 소프트웨어 및 컨테이너 이미지는 별도 공급 경로로 점검

3. 업데이트 사전 확인 및 적용

   ```bash command
   sudo apt-get -s upgrade
   sudo apt upgrade
   ```

4. 보류 및 추가 변경 패키지 확인

   사전 확인에서 제거·신규 설치·보류 항목의 업무 영향 검토. 보류된 보안 수정은 패키지별 종속성 해결 및 승인된 변경 계획에 따라 적용. 자동 업데이트는 조직의 재시작·유예 정책과 일치하도록 운영. 역할별 `/etc/apt/apt.conf.d/60-local-updates`에서 설정하고 `apt-config dump`로 최종 값 확인. apt.conf.d 파일은 사전식 순서로 읽지만 이후 `/etc/apt/apt.conf`와 명령행 옵션이 적용되므로 해당 재정의까지 대조. 목록형 설정은 누적되며 새 파일만으로 기존 목록이 제거되지 않으므로 필요한 범위의 `#clear` 처리 여부 확인

5. 실행 커널 및 장애 서비스 확인

   ```bash command
   uname -r
   systemctl --failed
   apt list --upgradable
   ```

6. 재시작 및 적용 증거 확인

   수정 전 라이브러리를 사용하는 서비스 재시작과 커널 업데이트의 재부팅 반영 확인. 배포판 도구가 안내하는 재부팅 요구 및 업무 기능 점검. 패키지 설치 성공만으로 실행 중 프로세스까지 수정된 것으로 판단 금지
