## 개요

### 점검 내용

NFS(Network File System)의 접근 통제 설정 적용 여부 점검

### 점검 목적

접근 권한이 없는 비인가자의 접근을 통제하기 위함

### 보안 위협

접근 통제 설정이 적절하지 않을 경우, 인증 절차 없이 비인가자가 디렉터리나 파일의 접근이 가능하며, 해당 공유 시스템에 원격으로 마운트하여 중요 파일을 변조하거나 유출할 위험이 존재함

### 참고

> **참고**
>
> NFSv4 사용만으로 암호화가 적용되지 않음. AUTH_SYS의 클라이언트 UID 신뢰와 root_squash는 강한 사용자 인증을 대신하지 않음

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 승인된 클라이언트와 최소 권한으로 export가 제한되고 설정 파일의 비인가 변경이 차단된 경우
- **취약:** 불특정 클라이언트 접근이 가능하거나 export 설정의 비인가 변경이 가능한 경우

### 조치 방법

NFS export의 클라이언트·권한·인증 범위 제한 및 설정 파일 보호

### 조치 시 영향

클라이언트 마운트와 애플리케이션 쓰기 실패 가능. UID 매핑 및 서비스 요구 권한 확인

## 점검 및 조치 사례

### RHEL 10

1. 유효 export 및 설정 파일 권한 확인

   ```bash command
   sudo exportfs -v
   sudo stat -c '%U:%G %a %n' /etc/exports
   sudo find /etc/exports.d -maxdepth 1 -name '*.exports' -ls
   ```

2. 승인된 클라이언트에 대한 최소 권한 설정

   ```text configuration
   /srv/share 192.0.2.10(ro,sync,root_squash)
   ```

3. 공유 범위 및 인증 방식 조정

   `/srv/share`와 `192.0.2.10`을 실제 공유 경로와 승인 클라이언트로 대체하여 역할별 `/etc/exports.d/application.exports`에 적용. `/etc/exports` 이후 이름이 점으로 시작하지 않는 `*.exports` 파일을 추가 export 표로 읽으므로 기존 파일의 같은 공유·클라이언트 정의를 함께 정리. 파일 번호만으로 기존 허용 범위가 덮어써진 것으로 판단 금지. 디렉터리와 파일이 없으면 root 소유로 생성 후 예시 저장. 불필요한 `*`, `no_root_squash` 및 쓰기 허용 제거. 클라이언트와 괄호 사이 공백 없이 작성. 비신뢰망은 Kerberos 기반 `sec=krb5p` 등 인증·암호화 구성을 별도로 적용

4. 설정 파일 보호 및 export 적용

   ```bash command
   sudo chown root:root /etc/exports /etc/exports.d /etc/exports.d/application.exports
   sudo chmod go-w /etc/exports /etc/exports.d /etc/exports.d/application.exports
   sudo exportfs -ra
   sudo exportfs -v
   ```

5. 클라이언트 접근 및 파일 권한 확인

   승인 클라이언트에서 필요한 마운트·읽기 동작 확인. 비승인 클라이언트의 접근 차단과 root_squash 적용 확인. 포함 파일에도 root 소유 및 비인가 쓰기 금지 적용
