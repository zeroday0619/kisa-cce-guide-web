## 개요

### 점검 내용

공유 서비스의 익명 접근 제한 설정 여부 점검

### 점검 목적

공유 서비스의 익명 접근을 제한하여 중요 정보의 노출을 방지하기 위함

### 보안 위협

공유 서비스의 익명 접근을 허용할 경우, 비인가자의 무단 접근으로 인한 중요 정보 탈취 또는 변조, 악성 코드 유포 등의 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 공유 서비스에 대해 익명 접근을 제한한 경우
- **취약:** 공유 서비스에 대해 익명 접근을 허용한 경우

### 조치 방법

Samba의 guest 접근 및 FTP 익명 접근 비활성화 설정

### 조치 시 영향

익명 공유를 사용하는 기존 클라이언트의 연결 중단 가능. 인증 계정 전환 및 Linux 파일 권한 확인

## 점검 및 조치 사례

### RHEL 10

1. Samba 설치 및 공유별 유효 설정 확인

   ```bash command
   rpm -q samba
   sudo testparm -s
   sudo net usershare info --long
   ```

2. 비공개 공유의 익명 접근 제한

   ```text configuration
   [global]
       map to guest = Never
       usershare allow guests = no

   [private]
       path = /srv/samba/private
       guest ok = no
       read only = yes
       valid users = @shareusers
   ```

3. 공유 경로 및 인증 사용자 권한 조정

   예시의 `private`, `/srv/samba/private`, `shareusers`를 실제 공유명·경로·승인 그룹으로 대체하여 `/etc/samba/smb.conf`의 해당 설정 수정. 기존 공유별 `guest ok = yes` 및 별도 usershare 설정 제거. 공유 디렉터리의 파일 권한과 ACL에서 guest 계정 접근 가능 여부 확인

4. 구문 검사 후 서비스 설정 적용

   ```bash command
   sudo testparm -s
   sudo smbcontrol all reload-config
   ```

5. 신규 연결의 접근 제한 확인

   기존 연결 종료 후 승인 계정의 정상 접근과 익명 접근 거부 확인. vsftpd 병행 사용 시 실제 설정 파일에서 `anonymous_enable=NO` 적용 후 서비스 재시작. NFS는 익명 로그인과 다른 인증 모델이므로 U-40의 export 접근 통제로 별도 점검
