## 개요

### 점검 내용

시스템 정책에 root 계정의 원격터미널 접속 차단 설정이 적용 여부 점검

### 점검 목적

관리자 계정 탈취로 인한 시스템 장악을 방지하기 위해 외부 비인가자의 root 계정 접근 시도를 원천적으로 차단하기 위함

### 보안 위협

root 계정은 운영체제의 모든 기능을 설정 및 변경이 가능하여(프로세스, 커널 변경 등) root 계정을 탈취하여 외부에서 원격을 이용한 시스템 장악 및 각종 공격으로(무차별 대입 공격, 사전 대입 공격 등) 인한 root 계정 사용 불가 위험이 존재함

### 참고

> **참고**
>
> `/etc/securetty`는 SSH 접근 통제 설정이 아님. `prohibit-password`는 root 공개키 로그인을 허용하므로 root 직접 접속 차단 기준을 충족하지 않음

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 원격터미널 서비스를 사용하지 않거나, 사용 시 root 직접 접속을 차단한 경우
- **취약:** 원격터미널 서비스 사용 시 root 직접 접속을 허용한 경우

### 조치 방법

SSH 유효 설정의 `PermitRootLogin`을 `no`로 설정하고 Telnet 등 불필요한 원격터미널 서비스 중지

### 조치 시 영향

root 직접 접속을 사용하는 백업 및 자동화 작업에 영향이 있으므로 전용 계정으로 이전 필요. 새 관리 세션 확인 전 기존 세션 유지

## 점검 및 조치 사례

### RHEL 10

1. 일반 관리 계정의 SSH 로그인 및 sudo 권한 확인 후 기존 관리 세션 유지. `192.0.2.10`은 실제 관리 클라이언트 주소로 변경

2. 주 설정, 포함 파일 및 접속 조건별 root 로그인 허용 여부 확인. `Match`에 호스트명 또는 로컬 주소 조건이 있으면 해당 값을 `-C` 인수에 추가

   ```bash command
   sudo grep -nE '^[[:space:]]*(Include|Match|PermitRootLogin)\b' /etc/ssh/sshd_config
   sudo grep -RnE '^[[:space:]]*(Include|Match|PermitRootLogin)\b' /etc/ssh/sshd_config.d
   sudo /usr/sbin/sshd -t
   sudo /usr/sbin/sshd -T -C user=root,addr=192.0.2.10 | grep '^permitrootlogin '
   systemctl list-unit-files 'ssh*'
   ```

3. `/etc/ssh/sshd_config`의 전역 영역에서 `Include /etc/ssh/sshd_config.d/*.conf` 사용 여부와 위치 확인. 포함 파일은 파일명 사전순으로 읽으며 `PermitRootLogin`은 먼저 읽힌 값 우선 적용. 역할별 `/etc/ssh/sshd_config.d/00-local-root-login.conf`에 다음 값 반영하되 더 먼저 읽히는 동일 설정과 `Match`별 허용 설정 조정. Include가 없으면 기존 설정을 보존하여 전역 영역에 연결하고 조건별 유효값 재확인

   ```text configuration
   PermitRootLogin no
   ```

4. 구문 검사 성공 후 실제 실행 중인 SSH 서비스에 설정 반영

   ```bash command
   sudo /usr/sbin/sshd -t
   sudo systemctl reload sshd.service
   ```

5. 새 관리 세션의 로그인 및 권한 상승 확인. 모든 적용 대상 접속 조건에서 `permitrootlogin no` 확인 및 root 직접 로그인 거부 확인
