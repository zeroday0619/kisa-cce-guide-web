## 개요

### 점검 내용

`/etc/hosts.lpd` 파일의 제거 및 권한 적절성 여부 점검

### 점검 목적

비인가자의 임의적인 `/etc/hosts.lpd` 변조를 막기 위해 `/etc/hosts.lpd` 파일 제거 또는 소유자 및 권한 관리하기 위함

### 보안 위협

`/etc/hosts.lpd` 파일의 접근 권한이 적절하지 않을 경우, 비인가자가 `/etc/hosts.lpd` 파일을 수정하여 허용된 사용자의 서비스를 방해할 수 있으며, 호스트 정보를 획득할 수 있는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** `/etc/hosts.lpd` 파일이 존재하지 않거나, 불가피하게 사용 시 `/etc/hosts.lpd` 파일의 소유자가 root이고, 권한이 600 이하인 경우
- **취약:** `/etc/hosts.lpd` 파일이 존재하며, 파일의 소유자가 root가 아니거나, 권한이 600 이하가 아닌 경우

### 조치 방법

불필요한 LPD 신뢰 파일을 제거하고 필요한 `hosts.lpd`는 root 소유·0600으로 보호

### 조치 시 영향

인쇄 서비스 또는 socket 중지 시 로컬·네트워크 인쇄에 영향이 있으므로 서버 역할과 사용 클라이언트 확인 필요

## 점검 및 조치 사례

### RHEL 10

1. 인쇄 패키지·활성 socket·515 및 631 포트 사용 주체 확인

   ```bash command
   rpm -qa | grep -E 'cups|lpr|lpd'
   systemctl list-sockets --all
   sudo ss -lntup
   ```

2. `hosts.lpd` 존재 시 소비하는 LPD 서비스 및 파일 권한 확인. 파일 부재만으로 CUPS 접근 정책을 판단하지 않음

   ```bash command
   sudo stat -c "%U %G %a %n" /etc/hosts.lpd
   sudo getfacl -p /etc/hosts.lpd
   ```

3. 불가피하게 사용 중인 파일만 root 소유 및 0600으로 보호. 불필요한 경우 LPD 의존성 제거 후 파일 정리

   ```bash command
   sudo chown root:root /etc/hosts.lpd
   sudo chmod 0600 /etc/hosts.lpd
   ```

4. 인쇄 기능이 불필요한 서버는 실제 설치된 인쇄 서비스·socket·path 활성화를 함께 중지. `UNIT`은 발견된 활성화 unit으로 대체

   ```bash command
   sudo systemctl disable --now UNIT
   ```

5. 인쇄 서버는 CUPS의 실제 접근 설정과 방화벽을 별도로 확인하고 승인 클라이언트의 인쇄 동작 및 비승인 접근 거부 확인
