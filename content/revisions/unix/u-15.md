## 개요

### 점검 내용

소유자가 존재하지 않는 파일 및 디렉터리의 존재 여부 점검

### 점검 목적

소유자가 존재하지 않는 파일 및 디렉터리를 제거 또는 관리하여 임의의 사용자가 해당 파일을 열람, 수정하는 행위를 사전에 차단하기 위함

### 보안 위협

소유자가 존재하지 않는 파일의 UID와 동일한 값으로 특정 계정의 UID를 변경하면 해당 파일의 소유자가 되어 모든 작업이 가능한 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 소유자가 존재하지 않는 파일 및 디렉터리가 존재하지 않는 경우
- **취약:** 소유자가 존재하지 않는 파일 및 디렉터리가 존재하는 경우

### 조치 방법

소유자가 확인되지 않는 파일 및 디렉터리의 생성 근거를 확인하여 승인 소유자로 변경하거나 보존 정책에 따라 제거

### 조치 시 영향

파일 탐색 시 I/O 부하가 발생할 수 있음. 중앙 인증 장애나 컨테이너 UID 매핑을 고아 파일로 오인하여 소유권 변경하지 않도록 확인 필요

## 점검 및 조치 사례

### RHEL 10

1. 로컬 마운트 및 중앙 계정 조회 상태 확인

   ```bash command
   findmnt -rn -o TARGET,FSTYPE,SOURCE
   getent passwd
   getent group
   ```

2. 대상 마운트별 소유자·그룹 미확인 객체 검색. `/srv/data`는 승인된 로컬 마운트 경로로 대체

   ```bash command
   sudo find /srv/data -xdev \( -nouser -o -nogroup \) -ls
   ```

3. 검색된 숫자 UID·GID를 계정 삭제 이력 및 업무 소유자 대장과 대조. NFS·동적 사용자·컨테이너 저장소는 해당 ID 매핑과 구분

4. 승인된 개별 객체만 소유권 변경. `USER:GROUP`과 파일 경로는 인계 결과에 맞게 대체

   ```bash command
   sudo chown -- USER:GROUP /srv/data/FILE
   stat -c "%u %g %a %n" /srv/data/FILE
   ```

5. 점검 마운트의 미확인 소유자 검색 재수행 및 인계받은 계정의 업무 접근 확인
