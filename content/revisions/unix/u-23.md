## 개요

### 점검 내용

불필요하거나 악의적인 파일에 SUID, SGID, Sticky bit 설정 여부 점검

### 점검 목적

불필요한 SUID, SGID, Sticky bit 설정 제거로 악의적인 사용자의 권한 상승을 방지하기 위함

### 보안 위협

SUID, SGID, Sticky bit 설정이 적절하지 않을 경우, SUID, SGID, Sticky bit가 설정된 파일로 특정 명령어를 실행하여 root 권한 획득이 가능한 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** SUID·SGID 및 capability 파일이 승인된 목록과 일치하고 불필요한 특권이 제거된 경우
- **취약:** 용도를 확인하지 않은 특권 파일 또는 불필요한 SUID·SGID·capability가 존재하는 경우

### 조치 방법

주요 실행 파일의 SUID·SGID 및 capability 필요성을 확인하여 불필요한 특권만 제거

### 조치 시 영향

특권 제거 시 로그인·비밀번호 변경 및 애플리케이션 실행에 영향이 있을 수 있으므로 필수 도구의 패키지 권한 유지

## 점검 및 조치 사례

### RHEL 10

1. 로컬 파일시스템별 SUID·SGID 파일과 capability 부여 파일 확인. `/srv/data`는 점검 마운트로 대체하고 `getcap`이 없으면 배포판의 capability 도구 설치 여부 확인

   ```bash command
   sudo find /srv/data -xdev -type f -perm /6000 -ls
   sudo getcap -r /srv/data
   ```

2. 각 파일의 소속 패키지 및 승인된 특권 필요성과 대조. `/PATH/FILE`과 `PACKAGE`는 조사 대상으로 대체

   ```bash command
   rpm -qf /PATH/FILE
   rpm -V PACKAGE
   ```

3. 불필요한 특권이 확인된 개별 파일만 해당 비트 제거. capability는 필요한 권한 목록과 대조하여 불필요한 경우 제거

   ```bash command
   sudo chmod u-s,g-s -- /PATH/FILE
   sudo setcap -r /PATH/FILE
   ```

4. 필수 sudo·passwd 도구의 모드는 배포판 패키지 기준으로 복구. `/tmp`·`/var/tmp` 등 공유 디렉터리의 sticky bit는 유지

5. 변경 대상 프로그램의 정상 실행과 특권 파일 목록 재확인. 패키지 갱신 후 다시 부여되는 권한도 변경 관리 대상으로 등록
