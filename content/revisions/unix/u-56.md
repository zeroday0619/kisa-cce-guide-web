## 개요

### 점검 내용

FTP 서비스에 비인가자의 접근 가능 여부 점검

### 점검 목적

접근 권한이 없는 비인가자의 접근을 통제하기 위함

### 보안 위협

FTP 서비스의 접근제한 설정이 적절하지 않을 경우, 인증 절차 없이 비인가자가 디렉터리나 파일에 접근할 수 있어 중요 파일 변조 및 유출을 시도할 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 특정 IP주소 또는 호스트에서만 FTP 서버에 접속할 수 있도록 접근 제어 설정을 적용한 경우
- **취약:** FTP 서버에 접근 제어 설정을 적용하지 않은 경우

### 조치 방법

FTP의 승인 출발지 및 사용자 제한과 제어·데이터 포트 접근 통제

### 조치 시 영향

제어 포트만 허용 시 로그인 후 전송 실패 가능. 현재 방화벽 관리 도구와 기존 정책 유지

## 점검 및 조치 사례

### RHEL 10

1. FTP 구현 및 실제 설정 경로 확인

   ```bash command
   rpm -q vsftpd
   systemctl cat vsftpd.service
   sudo ss -lntp
   ```

2. 설정 변경 전 기존 항목 확인

   `/etc/vsftpd/vsftpd.conf` 및 daemon 실행 인수에서 실제 설정 경로 확인. 중복 설정과 별도 인스턴스를 포함하여 호스트·클라우드 방화벽, 계정 허용 목록 및 listen 주소 확인

3. vsftpd 설정 수정

   ```text configuration
   userlist_enable=YES
   userlist_deny=NO
   userlist_file=/etc/vsftpd.allowed-users
   pasv_min_port=40000
   pasv_max_port=40100
   ```

4. 설정 경로 및 운영 조건 반영

   `/etc/vsftpd/vsftpd.conf`의 해당 항목 수정. `/etc/vsftpd.allowed-users`에 승인된 전송 계정을 한 줄씩 등록하고 root 소유 및 비인가 쓰기 금지 적용. 예시 passive 포트 범위는 실제 연결 규모와 방화벽 정책에 맞게 조정. 현재 관리 도구의 기존 허용 규칙에서 승인 출발지의 TCP 제어 포트와 passive 범위만 허용하고 광범위한 기존 허용 제거. IPv6·클라우드 방화벽도 동일하게 제한. 허용 계정 정상 전송 및 비승인 경로 차단 확인

5. 서비스 재시작 및 실행 상태 확인

   ```bash command
   sudo systemctl restart vsftpd.service
   systemctl status vsftpd.service
   sudo journalctl -u vsftpd.service -n 30 --no-pager
   ```

6. 현재 방화벽 정책 확인

   ```bash command
   sudo firewall-cmd --get-active-zones
   sudo firewall-cmd --list-all-zones
   ```
