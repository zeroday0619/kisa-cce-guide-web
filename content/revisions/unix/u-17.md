## 개요

### 점검 내용

시스템 시작 스크립트 파일 권한 적절성 여부 점검

### 점검 목적

시스템 시작 스크립트 파일을 관리자만 제어할 수 있게 하여 비인가자들의 임의적인 파일 변조를 방지하기 위함

### 보안 위협

시스템 시작 스크립트 파일의 소유권 및 권한 설정이 미흡할 경우, 비인가자가 스크립트의 내용 변경 등을 통해 시스템 침입 등 악용할 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 시스템 시작 스크립트 파일의 소유자가 root이고, 일반 사용자의 쓰기 권한이 제거된 경우
- **취약:** 시스템 시작 스크립트 파일의 소유자가 root가 아니거나, 일반 사용자의 쓰기 권한이 부여된 경우

### 조치 방법

systemd unit·drop-in 및 부팅 시 실행되는 특권 스크립트를 root 관리로 유지하고 비인가 쓰기 제거

### 조치 시 영향

실행 스크립트의 실행 권한 제거 시 서비스 시작 장애가 발생할 수 있음. `daemon-reload`는 실행 중인 서비스를 재시작하지 않으므로 내용 변경 시 적용 시점 확인

## 점검 및 조치 사례

### RHEL 10

1. 부팅 시 실행되는 서비스 및 실제 unit 경로 확인. `UNIT.service`는 점검 대상으로 대체

   ```bash command
   systemctl list-unit-files --type=service --state=enabled
   systemctl cat UNIT.service
   systemctl show UNIT.service -p FragmentPath -p DropInPaths -p ExecStart -p EnvironmentFiles
   ```

2. `DropInPaths`에 표시된 모든 unit·drop-in·실행 파일·환경 파일 및 상위 경로의 소유자와 쓰기 권한 확인. 다음 경로는 예시이며 실제 발견된 각 파일로 대체. `override.conf` 이외 역할별 `.conf`, 템플릿·인스턴스·이름 접두사 및 공통 `service.d`도 점검 대상에 포함. 심볼릭 링크는 대상 파일과 상위 경로까지 점검

   ```bash command
   namei -l /etc/systemd/system/UNIT.service.d/override.conf
   getfacl -p /etc/systemd/system/UNIT.service.d/override.conf
   ```

3. 배포판 unit은 소속 패키지와 대조하여 복구. `PACKAGE`는 조회한 패키지명으로 대체

   ```bash command
   rpm -qf /usr/lib/systemd/system/UNIT.service
   rpm -V PACKAGE
   ```

4. 로컬 unit과 특권 실행 스크립트의 비인가 쓰기 제거. 설정 변경은 패키지 unit 대신 `/etc/systemd/system/UNIT.service.d/` 아래 역할별 `.conf`로 관리. 파일명 순서와 동일 파일명의 `/etc`·`/run`·`/usr/lib` 우선순위를 확인하고 최종 `systemctl cat` 결과 대조. 파일별 실행 권한을 유지하며 재귀 chmod 금지

   ```bash command
   sudo chown root:root /etc/systemd/system/UNIT.service.d/override.conf
   sudo chmod 0644 /etc/systemd/system/UNIT.service.d/override.conf
   sudo systemctl daemon-reload
   ```

5. 다음 서비스 시작 시 유효 설정 확인. unit 내용까지 변경한 경우 유지보수 시간에 해당 서비스를 재시작하여 정상 작동 확인
