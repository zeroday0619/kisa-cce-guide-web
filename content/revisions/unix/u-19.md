## 개요

### 점검 내용

`/etc/hosts` 파일의 권한 적절성 여부 점검

### 점검 목적

`/etc/hosts` 파일을 관리자만 제어할 수 있게 하여 비인가자들의 임의적인 파일 변조를 방지하기 위함

### 보안 위협

`/etc/hosts` 파일에 비인가자가 쓰기 권한이 부여된 경우, 공격자는 `/etc/hosts` 파일에 악의적인 시스템을 등록하여, 이를 통해 정상적인 DNS를 우회하여 악성 사이트로의 접속을 유도하는 파밍(Pharming) 공격 등에 악용될 수 있는 위험이 존재함. `/etc/hosts` 파일에 소유자의 쓰기 권한이 부여된 경우, 일반 사용자 권한으로 `/etc/hosts` 파일에 변조된 IP주소를 등록하여 정상적인 DNS를 방해하고 악성 사이트로의 접속을 유도하는 파밍(Pharming) 공격 등에 악용될 수 있는 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** `/etc/hosts` 파일의 소유자가 `root`이고, 권한이 `644` 이하인 경우
- **취약:** `/etc/hosts` 파일의 소유자가 `root`가 아니거나, 권한이 `644` 이하가 아닌 경우

### 조치 방법

호스트의 `/etc/hosts`를 root 소유로 유지하고 비인가 쓰기 제거

### 조치 시 영향

이름 해석 변경 시 관리 접속 및 애플리케이션 연결에 영향이 있을 수 있음. 자동 생성 파일은 생성 설정을 함께 수정해야 변경 유지 가능

## 점검 및 조치 사례

### RHEL 10

1. 파일 소유자·권한·ACL 및 마운트 상태 확인

   ```bash command
   stat -c '%U %G %a %n' /etc/hosts
   getfacl -p /etc/hosts
   findmnt -T /etc/hosts
   ```

2. 일반 호스트의 파일 소유자와 모드 복구. cloud-init 또는 컨테이너가 관리하는 파일은 원본 템플릿·런타임 관리 설정에서 동일한 통제 적용

   ```bash command
   sudo chown root:root /etc/hosts
   sudo chmod 0644 /etc/hosts
   ```

3. 비인가 명명 ACL 제거 및 실제 파일 경로 재확인. 기존 IP·호스트명 매핑 내용은 권한 조치 중 유지

4. 주요 서비스 호스트명 조회 확인. `HOSTNAME`은 `/etc/hosts`에서 관리하는 실제 이름으로 대체

   ```bash command
   getent hosts HOSTNAME
   stat -c "%U %G %a %n" /etc/hosts
   ```
