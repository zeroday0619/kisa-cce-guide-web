## 개요

### 점검 내용

사용자 계정 로그인 실패 시 계정 잠금 임계값이 설정 여부 점검

### 점검 목적

계정 탈취 목적의 무차별 대입 공격 시 해당 계정을 잠금으로써 인증 요청에 응답하는 리소스 낭비를 차단하고 대입 공격으로 인한 비밀번호 노출 공격을 무력화하기 위함

### 보안 위협

계정 잠금 임계값이 설정되어 있지 않을 경우, 비밀번호 탈취 공격(무차별 대입 공격, 사전 대입 공격, 추측 공격 등)의 인증 요청에 대해 설정된 비밀번호가 일치할 때까지 지속적으로 응답하여 해당 계정의 비밀번호가 유출될 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 계정 잠금 임계값이 10회 이하의 값으로 설정된 경우
- **취약:** 계정 잠금 임계값이 설정되어 있지 않거나, 10회 이하의 값으로 설정되지 않은 경우

### 조치 방법

지원되는 `pam_faillock` 인증 경로에 계정 잠금 임계값을 10회 이하로 설정

### 조치 시 영향

PAM 순서 및 제어 플래그 오류 시 정상 로그인이 차단될 수 있음. root 잠금은 비상 콘솔 복구 정책과 함께 결정하며 공개키 인증·중앙 인증은 해당 인증 경로별 적용 여부 확인

## 점검 및 조치 사례

### RHEL 10

1. 현재 인증 profile 및 실패 집계 모듈 확인

   ```bash command
   sudo authselect current
   sudo authselect check
   grep -n pam_faillock /etc/pam.d/system-auth /etc/pam.d/password-auth
   ```

2. `/etc/security/faillock.conf`에 15분 동안 10회 실패 시 120초 잠금 설정. 기존에 더 낮은 임계값이 있으면 유지

   ```text configuration
   deny = 10
   fail_interval = 900
   unlock_time = 120
   silent
   ```

3. 현재 profile이 지원하는 실패 잠금 feature 활성화 및 구성 검사

   ```bash command
   sudo authselect enable-feature with-faillock
   sudo authselect check
   ```

4. 시험 계정으로 실제 비밀번호 인증 경로의 실패 집계 및 잠금·해제 확인. `TEST_USER`는 시험 계정으로 대체

   ```bash command
   sudo faillock --user TEST_USER
   sudo faillock --user TEST_USER --reset
   ```

### Ubuntu 26.04 LTS

1. 실제 PAM 인증 경로 및 설치된 실패 집계 모듈 확인

   ```bash command
   grep -nE 'common-auth|common-account|pam_faillock|pam_sss' /etc/pam.d/sshd /etc/pam.d/login /etc/pam.d/common-auth /etc/pam.d/common-account
   dpkg-query -L libpam-modules | grep pam_faillock
   ```

2. `/etc/security/faillock.conf`에 집계 시간·임계값·해제 시간 설정

   ```text configuration
   deny = 10
   fail_interval = 900
   unlock_time = 120
   silent
   ```

3. 로컬 `pam_unix` 인증만 사용하는 서버의 `/etc/pam.d/common-auth`에 다음 인증 흐름 반영. 기존 파일 백업 후 변경하고 `pam-auth-update`의 로컬 변경 유지 기능으로 관리. SSSD·LDAP·스마트카드 인증을 사용하는 서버는 각 인증 성공·실패 분기에도 동일한 집계가 연결되도록 기존 profile에서 조정

   ```text configuration
   auth required pam_faillock.so preauth
   auth [success=1 default=bad] pam_unix.so
   auth [default=die] pam_faillock.so authfail
   auth sufficient pam_faillock.so authsucc
   auth required pam_deny.so
   ```

4. 기존 관리 세션을 유지한 상태에서 시험 계정의 정상 로그인 및 임계값 도달 시 잠금 확인. 설정 변경 전후의 성공 경로와 실패 경로를 각각 확인

   ```bash command
   sudo faillock --user TEST_USER
   sudo faillock --user TEST_USER --reset
   ```
