## 개정 범위와 판단

지원되는 `pam_faillock` 경로로 로그인 실패를 제한한다. `pam_tally`·`pam_tally2` 또는 `/lib/security` 절대 경로를 현대 배포판에 복사하지 않는다.

## 배포판별 적용

RHEL 10은 현재 authselect profile과 feature를 보존하며 생성된 `system-auth`·`password-auth`를 직접 덮어쓰지 않는다. Ubuntu 26.04 LTS와 Debian 13은 설치된 PAM 모듈과 `pam-auth-update` profile을 확인한다. 중앙 인증의 정책은 로컬 PAM 설정만으로 대체하지 않는다.

## 점검 절차

`/etc/security/faillock.conf`와 실제 인증 stack에서 preauth·authfail·성공 및 account 처리를 확인한다. `faillock --user USER`는 지정한 시험 계정의 기록 확인에 사용한다. SSH 공개키와 중앙 인증은 적용 경로를 별도로 분류한다.

## 조치 절차

원문 임계값 10회 이하를 유지하여 예를 들어 `deny = 10`, `unlock_time = 120`을 설정하고 실패 집계 시간도 정책으로 정한다. RHEL에서는 현재 profile이 지원하는 `with-faillock` feature를 사용한다. Ubuntu·Debian에서는 PAM 제어 흐름을 검토한 profile로 관리하며 한 줄만 임의 추가하지 않는다.

다음은 `/etc/security/faillock.conf`에서 15분 동안 10회 실패하면 120초 잠그는 정책 예시다. 실제 운영의 집계 시간과 해제 시간은 승인된 정책으로 정한다.

```ini
deny = 10
fail_interval = 900
unlock_time = 120
```

설정 파일만으로 PAM 인증 경로가 바뀌지는 않는다. 기존 profile이 해당 feature를 지원하는 RHEL 환경에서는 `authselect current`와 `authselect check`로 상태를 확인한 뒤 `authselect enable-feature with-faillock`으로 관리한다. 중앙 인증에 적용되는 잠금과 로컬 잠금을 중복 적용하는지 확인한다. Ubuntu·Debian에는 authselect 명령을 적용하지 않는다.

## 영향과 검증

root 잠금 여부와 복구 절차를 명시한다. 무차별 실패 시험은 격리된 시험 계정에만 수행하고 운영 관리자 계정을 잠그지 않는다.

Verification required: 대상 배포판 VM에서 변경 전후 동작과 복구 절차를 검증해야 한다. 이 문서는 원문과 분리된 개정 초안이며 운영 적용 또는 사람 검토 완료를 의미하지 않는다.
