## 개요

### 점검 내용

su 명령어 사용을 허용하는 사용자를 지정한 그룹이 설정 여부 점검

### 점검 목적

su 관련 그룹만 su 명령어 사용 권한이 부여되어 있는지 점검하여 su 그룹에 포함되지 않은 일반 사용자의 su 명령 사용을 원천적으로 차단하는지 확인하기 위함

### 보안 위협

무분별한 사용자 변경으로 타 사용자 소유의 파일을 변경할 수 있으며 root 계정으로 변경하는 경우 관리자 권한을 획득할 수 있는 위험이 존재함

### 참고

> **참고**
>
> `trust` 옵션은 그룹 구성원의 비밀번호 인증을 생략할 수 있으므로 사용하지 않음. sudo 권한은 별도 정책으로 관리

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** su 명령어를 특정 그룹에 속한 사용자만 사용하도록 제한된 경우
- **취약:** su 명령어를 모든 사용자가 사용하도록 설정된 경우

### 조치 방법

`/etc/pam.d/su`에 `pam_wheel` 기반 허용 그룹을 설정하여 su 사용 제한

### 조치 시 영향

그룹 변경은 새 로그인 세션부터 반영됨. 서비스 계정 전환을 사용하는 배치 작업의 실행 경로 확인 필요

## 점검 및 조치 사례

### RHEL 10

1. PAM su 인증 경로 및 허용 그룹 확인

   ```bash command
   grep -nE 'pam_rootok|pam_wheel|include|substack|@include' /etc/pam.d/su
   getent group wheel
   id USER
   ```

2. 승인된 사용자만 `wheel` 그룹에 추가. 그룹이 없는 경우 먼저 생성하며 `USER`는 승인 계정으로 대체

   ```bash command
   sudo groupadd -f wheel
   sudo usermod -aG wheel USER
   ```

3. `/etc/pam.d/su`의 `pam_rootok` 다음, 일반 인증 성공 처리 이전에 그룹 제한 설정. 기존 제한이 있으면 중복 추가하지 않고 유효 설정 수정

   ```text configuration
   auth required pam_wheel.so use_uid group=wheel
   ```

4. 새 로그인에서 허용 그룹 사용자의 su 동작과 비허용 사용자의 거부 확인. `su-l`을 사용하는 경우 해당 PAM 파일의 `su` 포함 여부도 확인
