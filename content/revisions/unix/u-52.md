## 개요

### 점검 내용

원격 접속 시 Telnet 프로토콜 사용 여부 점검

### 점검 목적

취약한 Telnet 프로토콜을 비활성화함으로써 계정 및 중요 정보 유출 방지하기 위함

### 보안 위협

원격 접속 시 Telnet 프로토콜을 사용할 경우, 데이터가 평문으로 전송되어 비인가자가 스니핑을 통해 계정 및 중요 정보를 외부로 유출할 위험이 존재함

### 참고

> **참고**
>
> Telnet 클라이언트 설치와 서버 실행 구분. /etc/securetty 수정만으로 Telnet 서버가 비활성화되지 않음

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 원격 접속 시 Telnet 프로토콜을 비활성화하고 있는 경우
- **취약:** 원격 접속 시 Telnet 프로토콜을 사용하는 경우

### 조치 방법

SSH 접속 및 복구 경로 확보 후 Telnet 서버 비활성화 설정

### 조치 시 영향

구형 원격 관리 스크립트와 장비 연결 중단 가능. SSH 로그인 및 권한 상승 확인

## 점검 및 조치 사례

### RHEL 10

1. 설치된 서버 패키지 및 서비스 활성화 경로 확인

   ```bash command
   rpm -qa | grep -Ei 'telnet'
   systemctl list-unit-files | grep -Ei 'telnet'
   systemctl list-sockets --all
   sudo ss -lntup
   ```

2. 표준 포트 및 별도 실행 설정 확인

   TCP 23의 수신 프로세스와 실행 인수 확인. `/etc/inetd.conf`, `/etc/xinetd.d/`가 존재하는 경우 해당 서비스 항목 확인. 패키지 미설치 및 포트 부재만으로 비활성 여부를 판단하지 않고 사용자 지정 서비스도 확인

3. 불필요한 서버 활성화 설정 제거

   확인된 서비스와 socket 이름을 지정하여 `systemctl disable --now UNIT` 실행. `UNIT`은 실제 해당 unit 이름으로 대체. inetd는 해당 항목 주석 처리, xinetd는 해당 항목의 `disable = yes` 설정 후 사용 중인 관리자 서비스 재시작. 다른 서비스를 함께 제공하는 inetd 전체 중지 금지

4. 서비스 및 socket 재활성화 여부 확인

   ```bash command
   systemctl list-units --all | grep -Ei 'telnet'
   systemctl list-sockets --all
   sudo ss -lntup
   ```
