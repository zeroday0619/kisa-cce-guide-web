## 개요

### 점검 내용

안전한 SNMP 버전 사용 여부 점검

### 점검 목적

안전한 SNMP 버전 사용으로 전송되는 데이터를 보호하기 위함

### 보안 위협

SNMP 메시지의 인증 또는 암호화가 적용되지 않을 경우, 관리 정보 도청 및 비인가 메시지 처리 위험이 존재함

### 참고

> **참고**
>
> v3라는 버전만으로 인증과 암호화가 보장되지 않으므로 authPriv 보안 수준을 함께 적용

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** SNMP를 사용하지 않거나 모든 허용 접근에 v3 authPriv가 적용된 경우
- **취약:** v1/v2c 또는 인증·암호화가 없는 SNMP 접근이 허용된 경우

### 조치 방법

SNMPv3 authPriv 적용 및 v1/v2c·암호화 없는 접근 제거

### 조치 시 영향

구형 수집기 및 알고리즘 호환성에 따라 수집 중단 가능. 사용자·engine ID·시각 상태 확인

## 점검 및 조치 사례

### RHEL 10

1. SNMP 패키지 및 실행 역할 확인

   ```bash command
   rpm -q net-snmp
   systemctl cat snmpd.service
   systemctl status snmpd.service snmptrapd.service
   sudo ss -lnup
   ```

2. 유효 SNMP 버전 및 보안 수준 확인

   `/etc/snmp/snmpd.conf`와 include 파일에서 v1/v2c community 접근 항목 및 v3 rouser·rwuser·access 설정 확인. noAuthNoPriv·authNoPriv·authPriv 구분. 비밀값이 포함된 파일의 전체 내용을 보고서에 복사하지 않도록 관리

3. 인증·암호화를 사용하는 v3 사용자 준비

   서버와 수집기의 공통 지원 인증·암호화 알고리즘을 확인하여 v3 사용자 생성. 패키지 제공 사용자 생성 도구의 대화형 비밀 입력 또는 보호된 비밀 배포 경로 사용. Net-SNMP 영구 상태 파일은 daemon 중지 상태에서 공식 사용자 생성 절차로 관리

4. 암호화를 요구하는 읽기 전용 사용자 설정

   ```text configuration
   rouser monitor priv
   ```

5. 기존 비보호 접근 제거

   monitor를 실제 v3 사용자로 대체하고 `/etc/snmp/snmpd.conf`에 반영. 수집기를 authPriv로 전환 후 rocommunity·rwcommunity 및 v1/v2c com2sec/group/access 경로 제거. 별도 v3 access 규칙이 낮은 보안 수준을 허용하지 않는지 확인

6. 서비스 재시작 및 상태 확인

   ```bash command
   sudo systemctl restart snmpd.service
   systemctl status snmpd.service
   ```

7. 수집 연결의 보안 수준 확인

   실제 관리 서버에서 authPriv로 정상 지표 수집 확인. 과거 community와 암호화 없는 접근의 허용 정책이 제거되었는지 대조. engine ID 및 시간 동기화 변화에 따른 수집 오류 확인
