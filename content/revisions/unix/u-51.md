## 개요

### 점검 내용

DNS 서비스의 취약한 동적 업데이트 설정 여부 점검

### 점검 목적

DNS 서비스의 동적 업데이트를 비활성화함으로써 신뢰할 수 없는 원본으로부터 업데이트를 받아들이는 위험을 차단하기 위함

### 보안 위협

DNS 서버에서 동적 업데이트를 사용할 경우, 악의적인 사용자에 의해 신뢰할 수 없는 데이터가 받아들여질 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 동적 갱신이 비활성화되거나 인증된 주체와 필요한 레코드로 제한된 경우
- **취약:** 비인증 갱신 또는 승인 범위를 초과한 레코드 변경이 가능한 경우

### 조치 방법

동적 갱신 비활성화 또는 인증된 주체의 최소 레코드 범위로 제한

### 조치 시 영향

DHCP·AD 이름 등록 중단 가능. 동적 zone 관리 절차 및 journal 보존

## 점검 및 조치 사례

### RHEL 10

1. 실행 인수 및 포함 설정 파일 확인

   ```bash command
   systemctl cat named.service
   sudo named-checkconf /etc/named.conf
   ```

2. zone별 유효 접근 정책 확인

   zone과 include 파일의 `allow-update` 또는 `update-policy` 확인. DHCP·AD 연동 및 TSIG/GSS-TSIG 주체별 수정 권한 대조

3. 불필요한 동적 갱신 차단

   ```text configuration
   allow-update { none; };
   ```

4. 기존 zone에 정책 적용

   갱신이 불필요한 기존 zone 블록에 반영. update-policy가 있으면 두 방식을 함께 사용하지 않고 해당 zone의 기존 정책을 비활성 정책으로 변경. 필요한 동적 zone은 인증된 키별 이름·레코드 유형을 최소 범위로 제한

5. 구문 검사 및 설정 적용

   ```bash command
   sudo named-checkconf /etc/named.conf
   sudo rndc reconfig
   sudo rndc status
   ```

6. 서비스 종속 동작 확인

   승인 DHCP·AD 갱신 및 이름 해석 확인. 동적 zone의 journal을 임의 삭제하거나 zone 파일을 직접 덮어쓰지 않도록 관리
