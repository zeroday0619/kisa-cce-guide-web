## 개요

### 점검 내용

tftp, talk, ntalk 서비스의 활성화 여부 점검

### 점검 목적

안전하지 않거나 불필요한 서비스를 제거함으로써 시스템 보안성 및 리소스의 효율적 운용하기 위함

### 보안 위협

사용하지 않는 서비스나 취약점이 발표된 서비스 운용 시 공격 시도 가능한 위험이 존재함

### 참고

> **참고**
>
> TFTP는 자체 사용자 인증을 제공하지 않으므로 중요한 정보와 비밀키를 전송 루트에 저장하지 않도록 설정

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** 불필요한 tftp, talk, ntalk가 비활성화되고 필수 TFTP가 승인 범위로 격리된 경우
- **취약:** 불필요한 tftp, talk, ntalk가 활성화되거나 TFTP의 접근 범위가 제한되지 않은 경우

### 조치 방법

불필요한 tftp, talk, ntalk 서버 및 활성화 socket 비활성화 설정

### 조치 시 영향

PXE 설치 및 장비 부팅 중단 가능. 필요한 TFTP는 승인 관리망과 읽기 전용 배포 경로로 격리

## 점검 및 조치 사례

### RHEL 10

1. 설치된 서버 패키지 및 서비스 활성화 경로 확인

   ```bash command
   rpm -qa | grep -Ei 'tftp|talk|ntalk'
   systemctl list-unit-files | grep -Ei 'tftp|talk|ntalk'
   systemctl list-sockets --all
   sudo ss -lntup
   ```

2. 표준 포트 및 별도 실행 설정 확인

   UDP 69, 517, 518의 수신 프로세스와 실행 인수 확인. `/etc/inetd.conf`, `/etc/xinetd.d/`가 존재하는 경우 해당 서비스 항목 확인. 패키지 미설치 및 포트 부재만으로 비활성 여부를 판단하지 않고 사용자 지정 서비스도 확인

3. 불필요한 서버 활성화 설정 제거

   확인된 서비스와 socket 이름을 지정하여 `systemctl disable --now UNIT` 실행. `UNIT`은 실제 해당 unit 이름으로 대체. inetd는 해당 항목 주석 처리, xinetd는 해당 항목의 `disable = yes` 설정 후 사용 중인 관리자 서비스 재시작. 다른 서비스를 함께 제공하는 inetd 전체 중지 금지

4. 서비스 및 socket 재활성화 여부 확인

   ```bash command
   systemctl list-units --all | grep -Ei 'tftp|talk|ntalk'
   systemctl list-sockets --all
   sudo ss -lntup
   ```
