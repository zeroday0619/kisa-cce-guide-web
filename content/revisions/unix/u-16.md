## 개요

### 점검 내용

`/etc/passwd` 파일 권한 적절성 여부 점검

### 점검 목적

`/etc/passwd` 파일을 관리자만 제어할 수 있게 하여 비인가자들의 임의적인 파일 변조를 방지하기 위함

### 보안 위협

비인가자가 `/etc/passwd` 파일의 사용자 정보를 변조하여 Shell 변경, 사용자 추가/제거 등 root 계정을 포함한 사용자 권한 획득 위험이 존재함

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** `/etc/passwd` 파일의 소유자가 root이고, 권한이 644 이하인 경우
- **취약:** `/etc/passwd` 파일의 소유자가 root가 아니거나, 권한이 644 이하가 아닌 경우

### 조치 방법

`/etc/passwd`를 root 소유로 유지하고 비인가 쓰기 권한 제거

### 조치 시 영향

일반 읽기를 제거하면 계정 이름 조회에 영향이 있을 수 있으므로 배포판의 일반적인 0644 권한 유지

## 점검 및 조치 사례

### RHEL 10

1. 실제 파일과 상위 경로의 소유자·권한 및 ACL 확인. `getfacl`이 없으면 배포판의 `acl` 패키지 도구 사용

   ```bash command
   stat -c '%U %G %a %n' /etc/passwd
   namei -l /etc/passwd
   getfacl -p /etc/passwd
   ```

2. root 소유 및 기본 읽기 권한 복구

   ```bash command
   sudo chown root:root /etc/passwd
   sudo chmod 0644 /etc/passwd
   ```

3. 명명된 사용자·그룹 ACL에 불필요한 권한이 있으면 해당 ACL만 제거. `USER`는 비인가 ACL 주체로 대체

   ```bash command
   sudo setfacl -x u:USER /etc/passwd
   getfacl -p /etc/passwd
   ```

4. 계정 파일 일관성과 사용자 조회 확인

   ```bash command
   sudo pwck -r
   getent passwd root
   ```
