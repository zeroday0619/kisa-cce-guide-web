## 개정 범위와 판단

로컬 비밀번호 변경 경로에 길이·품질·재사용 제한과 유효기간 정책이 실제 적용되어야 한다. 설정 파일의 존재만으로 양호 판정하지 않는다.

## 배포판별 적용

RHEL 10은 현재 authselect profile과 feature를 보존하며 생성된 `system-auth`·`password-auth`를 직접 덮어쓰지 않는다. Ubuntu 26.04 LTS와 Debian 13은 설치된 PAM 모듈과 `pam-auth-update` profile을 확인한다. 중앙 인증의 정책은 로컬 PAM 설정만으로 대체하지 않는다.

## 점검 절차

RHEL은 `authselect current`와 `authselect check`, Ubuntu·Debian은 `/etc/pam.d/common-password`와 활성 PAM profile을 확인한다. `pwquality.conf.d`의 파일을 이름순으로 먼저 읽고 주 `pwquality.conf`를 읽는 순서 및 PAM 인수의 우선순위와 `chage -l USER`의 기존 계정 값을 대조한다.

## 조치 절차

조직 기준을 `pam_pwquality`와 `pam_pwhistory`의 실제 password stack에 연결한다. 원문 기준을 유지하는 경우 최소 8자·문자 종류·최소 1일·최대 90일·최근 4회 제한을 명시하고 더 긴 비밀번호 기준은 별도 승인한다. `login.defs` 변경은 기존 계정에 소급되지 않으므로 대상별 변경 계획을 수립한다.

다음은 영문·숫자·특수문자를 포함하는 최소 8자 정책의 `pwquality.conf` 설정 예시다. 기존의 더 강한 정책을 낮추지 않으며 앞서 확인한 파일·PAM 인수 우선순위에 맞춰 반영한다.

```ini
minlen = 8
minclass = 3
dcredit = -1
ocredit = -1
ucredit = 0
lcredit = 0
enforce_for_root
```

`pam_pwhistory`에는 최소 `remember=4`와 필요한 root 적용 정책을 별도로 설정한다. 이 설정 파일만 작성해서는 모듈이 활성화되지 않는다. RHEL은 기존 authselect profile을 유지하는 지원 feature 또는 custom profile로, Ubuntu·Debian은 검토된 `pam-auth-update` profile로 password stack에 연결한다. 성공·실패 제어 플래그와 `use_authtok` 연결을 기존 인증 흐름과 함께 검토한다.

`/etc/login.defs`의 신규 계정 기본값 예시는 다음과 같다. 기존 계정은 `chage -l USER`로 별도 확인하고 서비스 계정 영향 검토 후 개별 적용한다.

```text
PASS_MIN_DAYS 1
PASS_MAX_DAYS 90
```

## 영향과 검증

서비스 비밀번호 만료는 연동 장애를 유발한다. `pam_pwquality`와 `pam_pwhistory`의 `enforce_for_root` 적용 여부, root 변경 경로와 중앙 IdP 정책을 별도로 확인하고 긴급 관리자 접근을 보존한다.

Verification required: 대상 배포판 VM에서 변경 전후 동작과 복구 절차를 검증해야 한다. 이 문서는 원문과 분리된 개정 초안이며 운영 적용 또는 사람 검토 완료를 의미하지 않는다.
