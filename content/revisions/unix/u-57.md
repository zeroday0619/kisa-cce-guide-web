## 개요

### 점검 내용

FTP 서비스에 root 계정 접근 제한 설정 여부 점검

### 점검 목적

root 계정의 FTP 직접 접속을 제한하여 root 비밀번호 정보 노출을 방지하기 위함

### 보안 위협

FTP의 root 직접 접속이 허용될 경우, 관리자 인증정보 노출 및 과도한 파일 접근 권한으로 중요 정보 유출·변조 위험이 존재함

### 참고

> **참고**
>
> SFTP는 ftpusers를 사용하지 않으므로 SSH의 root 로그인 및 Match 정책으로 별도 제한

## 점검 대상 및 판단 기준

### 대상

RHEL 10, Ubuntu 26.04 LTS, Debian 13

### 판단 기준

- **양호:** root 계정 접속을 차단한 경우
- **취약:** root 계정 접속을 허용한 경우

### 조치 방법

FTP의 실제 유효 거부 정책에 root 및 불필요한 특권 계정 등록

### 조치 시 영향

root 직접 전송을 사용하는 애플리케이션 중단 가능. 허용 목록과 거부 목록 의미 구분

## 점검 및 조치 사례

### RHEL 10

1. FTP 구현 및 실제 설정 경로 확인

   ```bash command
   rpm -q vsftpd
   systemctl cat vsftpd.service
   sudo ss -lntp
   ```

2. 설정 변경 전 기존 항목 확인

   `/etc/vsftpd/vsftpd.conf` 및 daemon 실행 인수에서 실제 설정 경로 확인. 중복 설정과 별도 인스턴스를 포함하여 FTP PAM의 pam_listfile 참조 경로와 userlist_enable·userlist_deny·userlist_file의 유효 관계 확인

3. vsftpd 설정 수정

   ```text configuration
   userlist_enable=YES
   userlist_deny=YES
   userlist_file=/etc/vsftpd.denied-users
   ```

4. 설정 경로 및 운영 조건 반영

   `/etc/vsftpd/vsftpd.conf`의 해당 항목 수정. 예시는 거부 목록 방식. `/etc/vsftpd.denied-users`에 root 및 전송이 불필요한 특권 계정을 한 줄씩 등록하고 root 소유·비인가 쓰기 금지 적용. 기존 userlist_deny=NO 허용 목록 정책 사용 시 거부 방식으로 전환하지 않고 허용 목록에서 특권 계정 제외. PAM의 pam_listfile이 참조하는 ftpusers 경로에서도 root 차단 확인. 정상 사용자 접속 및 root 거부 확인

5. 서비스 재시작 및 실행 상태 확인

   ```bash command
   sudo systemctl restart vsftpd.service
   systemctl status vsftpd.service
   sudo journalctl -u vsftpd.service -n 30 --no-pager
   ```
